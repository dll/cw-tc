# migrations · 数据库迁移

> **本目录的唯一定义来源是 `docs/数据字典-v1.md` §8「迁移与种子」** ——
> 字段、约束、索引、枚举**一律以那份文档为准**；本目录只放它的落地 SQL。
> 本文档只讲**怎么放、怎么跑、怎么不踩坑**。

## 命名与顺序

- 文件名：`NNNN_<snake_case_主题>.sql`，四位编号，**只增不改**。
- **已执行过的迁移文件不得修改**（改了不会重跑，只会让环境之间产生"看不见的差异"）。
  要改就**新增一个编号**。
- 编号与内容对照见 `docs/数据字典-v1.md` §8（当前 **0001~0019**）。

## 执行

```bash
# 本地开发（幂等：已执行的会跳过）
make migrate                       # 待实现：内部调用 cmd/migrate 或 psql + migration 表

# 手工执行单个（仅在排查时用）
psql "$CWTC_DB_DSN" -f migrations/0001_enable_extensions.sql
```

- **开发期**：`make migrate` 一条命令跑完。
- **生产**：**发布流水线内执行，先迁移后切流量**（PRD §12.3）；迁移**必须可重复执行**。
- **回滚**：DML 型回滚用业务接口（如撤证），**DDL 不写 down 脚本** ——
  生产回滚靠"备份恢复"，不靠反向 DDL（反向 DDL 在数据面前经常是错的）。

## 铁律

1. **迁移必须幂等**：`CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` /
   `DO $$ ... EXCEPTION WHEN duplicate_object ...`。
2. **不删列、不改类型**（首发阶段）：加列给默认值；确需变更走"新列 + 回填 + 切换"三步。
3. **强制项靠代码启动校验，不靠迁移**：加密 / HMAC / 会话密钥缺失则服务**拒绝启动**
   （`internal/config`），**不在迁移里给默认密钥**（那等于把密钥写进版本库）。
4. **种子数据用 upsert**（`ON CONFLICT DO UPDATE`），保证重跑结果一致。
5. **一次迁移只做一件事**，便于定位与手工补跑。

> ⚠️ **为什么不一次性把 19 个都建出来**：迁移是**跟着功能走**的（先有表才有代码，或反之），
> 一次性写完 19 个只会得到一堆**没被任何代码验证过的 DDL** —— 那种"看起来齐了"的假完成，
> 比空目录更危险。**按批次写、写一个跑一个。**
