# 第三课堂 · M2「付费可下单」详细要求（v1）

> **本文是什么**：M2 里程碑的**可执行要求** —— 资质清单、渠道形态、订单与资金要求、技术实现要求、
> 验收清单、排期与关键路径，以及**需要公司/刘老师提供的东西**。
> **本文不是什么**：不是接口契约（见 `docs/API接口参考-v1.md`），也不是需求全文（见 `docs/PRD-第三课堂-v2.md` §7.3 / §9.7）。
>
> | 项 | 内容 |
> |---|---|
> | 版本 | **v1.0**（配套 PRD v2.14 · API v1.9） |
> | 日期 | 2026-10-04 |
> | 状态 | **M2 前置 = 资质；技术侧可先在沙箱跑通，资质到位后切换生产** |

## 〇、结论先行（三句话）

1. **M2 唯一的硬卡点是资质**：微信支付 / 支付宝商户号需要**企业资质**（营业执照 + 法人证件 + 对公账户）
   —— **不是技术问题，是材料与审批周期问题**，**未下号前支付功能不得上线**（PRD §9.7）。
2. **技术侧可以先把沙箱跑通**：两个渠道都有沙箱；沙箱能验完验签、幂等、状态机、对账、退款撤证联动全套逻辑，
   下号后只需**换证书与密钥、改配置**，**不改代码**（这是"支付走网关层"的直接收益）。
3. **本阶段真正会出事的三件事**：① **重复下单导致重复支付**；② **回调不验签**；
   ③ **对账有差异却没人发现**。本文的验收清单就是照这三件事写的。

|---|---|---|---|---|

- **经营类目怎么选**（重要，影响费率与审核）：本产品是**在线课程 + 能力认证**，

  具体可报类目与所需材料**以渠道当期要求为准**，签约时确认后**回填本文表格**。

> ⚠️ **规矩**：本文**不写费率与结算周期的具体数字** —— 它们以签约合同为准，随时会变。
> **任何写进对外文案或站内的费率数字，都必须来自合同原件**（铁律二）。

## 二、渠道与产品形态（定案）

| 渠道 | 产品 | 用在哪 | 为什么这么选 |
|---|---|---|---|
| **微信支付** | **Native（扫码）** | Web 端 | 桌面浏览器最通用，不依赖微信内打开 |
| **微信支付** | **APP 支付** | Android App | App 内直接调起，转化率最高 |
| **支付宝** | **当面付（扫码）** | Web 端 | 与微信互为兜底 |
| **支付宝** | **APP 支付** | Android App | 同上 |

**明确不做的（首发）**：H5 支付（需额外签约且体验一般）· JSAPI（不做微信内打开）·
微信小程序支付（产品不做小程序，PRD §16-11）· 分期 / 花呗专项 · 组合支付 · 部分退款（P1）。

- **两个渠道都要上**（§16-12 已结案）：单一渠道会因风控、限额或用户习惯直接丢单；
  两渠道互为兜底，**其一不可用时另一条通路仍能成交**。
- **回调地址**：`https://cw-tc.ccit-agent.cn/api/v1/pay/{channel}/notify`，**必须 HTTPS 公网可达**。

## 三、订单与资金要求

### 3.1 订单状态机（要求，不是建议）

```
                     ┌──────────── 超时 30 分钟（可配） ─────────────┐
                     ▼                                              │
  ┌──────────┐  创建  ┌────────────┐  支付成功（回调/查单）  ┌──────────┐
  │  (无)    │ ─────▶ │  pending   │ ─────────────────────▶ │  paid    │
  └──────────┘        │  待支付     │                        │  已支付   │
                      └────────────┘                        └────┬─────┘
                             ▲                                   │ 退款
                       复用同一订单                              ▼
                      （连点 / 重试）                        ┌──────────┐
                                                            │ refunded │
                      ┌────────────┐                        │  已退款   │
                      │  closed    │ ◀── 主动关闭 / 超时      └──────────┘
                      │  已关闭     │
                      └────────────┘
```

### 3.2 硬要求（每条都要有测试）

| # | 要求 | 为什么 |
|---|---|---|
| 1 | **同一学员 + 同一课程，最多一笔「待支付」订单**（部分唯一索引 `UNIQUE(student_id, course_code) WHERE status='pending'`） | 连点 / 弱网重试会产生两笔订单 → **一次课程付两次钱**，直接的资金事故 |
| 2 | 下单请求带 **`request_id`**（幂等键），服务端去重 | 客户端重试不该产生新订单 |
| 3 | **待支付订单超时自动关闭**（默认 **30 分钟**，`system_config` 可配） | 避免僵尸订单堆积、避免"付了但订单已废" |
| 4 | **订单快照课程名与当时价格** | 事后改价不得影响已下单的订单 |
| 5 | **订单号规则**：全局唯一、**不可猜测**、**不含个人信息** | 订单号会出现在回调与日志中 |
| 6 | **金额一律以 `bigint` 分为单位**（`*_cents`），**绝不用浮点** | 浮点=对不上账 |
| 7 | **前端传来的金额一律不可信**：金额由服务端按课程当前价计算 | 改价攻击 |
| 8 | **支付成功 → 权益生效 ≤ 3 秒** | M2 验收物 |

### 3.3 退款（与证书联动，PRD §7.3 G-4 / §16-22）

| 时机 | 谁能退 | 连带动作 |
|---|---|---|
| 未参加测评 | **学员自助**（7 日内） | 撤权益 |
| 已考未发证 | **学员自助** | 撤权益 |
| **已发证** | **仅管理员特批** | 撤权益 + **撤销证书**（原因「订单已退款」，**原编号不可复活**） |

- **要求**：撤权益与撤证书**必须在同一业务操作内完成**，失败**整体回滚并告警** ——
  **不得出现"退了款、证书仍有效"的中间态**（这是本产品最容易出合规事故的一处）。
- **渠道退款失败**：**重试 + 告警 + 人工介入**；退款状态**对学员可见**。
- **退款窗口 7 日**：存 `system_config`（`pay.refund_self_service_days`），**不写死代码**。

## 四、技术实现要求

| # | 要求 | 落点 |
|---|---|---|
| 1 | **回调必须验签**，验签失败**一律拒绝并告警**（不是记日志放过） | `/pay/{channel}/notify` |
| 2 | **回调必须幂等**：同一笔重复回调只生效一次；**以「订单号 + 渠道交易号」为幂等键** | 支付流水表唯一约束 |
| 3 | **金额二次核对**：订单金额 vs 渠道金额，不一致**不入账 + 告警** | 回调处理 |
| 4 | ⚠️ **支付回调不携带手机号** → **对账一律用「订单号 + 渠道交易号」**，**不得用手机号做对账键** | 对账任务 |
| 5 | **双通道确认**：异步回调（主）+ **主动查单（辅）** —— 回调丢失时由查单补齐 | 定时任务 |
| 6 | **每日对账**：笔数 + 金额 + 退款，**差异必须为 0**；有差异**告警 + 生成差异明细** | `/admin/reconcile` |
| 7 | **同一订单只允许一条成功支付流水**（唯一约束） | 资金表 |
| 8 | **所有资金动作写审计**：谁、何时、原值 → 新值（退款 / 改价 / 下架） | `audit_log` |
| 9 | **回调日志脱敏**：日志里不得出现完整手机号 / 身份证号（铁律 3） | 访问日志过滤器 |
| 10 | **渠道参数只走 `shared/.env`**，**绝不入库、绝不入响应**；配置页只显示"已配置 / 未配置" | PRD §12.2 / §7.10.6 |
| 11 | **平台证书 / 密钥支持轮换**：换证书不重启服务、有演练步骤 | 部署手册 |
| 12 | **渠道不可用要如实反映**（下单失败给明确原因），**不得伪造支付成功** | 客户端与接口 |

## 五、客户端要求

- **App**：调起渠道 SDK；**包名与签名必须与商户号登记的一致**（不一致会直接报签名错误）；
  支付结果**以服务端订单状态为准**，**不得以客户端回调为准**。
- **Web**：展示二维码 + **轮询订单状态**（`GET /orders/{orderNo}`）；二维码**设有效期并提示过期可刷新**。
- **不得在客户端持久化任何支付凭据**；**不得把预付参数写进 URL**（会进日志与浏览器历史）。
- **弱网与返回**：用户支付后返回 App，**必须主动查一次订单状态**（不能只等轮询间隔）。

## 六、验收清单（**逐条可执行**）

- [ ] 连点「购买」10 次 → **只产生 1 笔待支付订单**（并发单测 + 手工验证）
- [ ] 同一订单**重复回调 10 次** → 只生效 1 次，权益只开通 1 次
- [ ] **回调验签失败** → 拒绝 + 告警（构造篡改报文测试）
- [ ] **篡改金额的回调** → 拒绝 + 告警
- [ ] 支付成功后 **≤ 3 s 内课程解锁**（M2 验收物）
- [ ] **回调丢失场景**：手动停掉回调入口，靠查单在 N 分钟内补齐（记录实测耗时）
- [ ] 待支付订单超时 → 自动关闭；**关闭后可重新下单且订单号不同**
- [ ] 管理员退款（已发证）→ ① 权益撤 ② **验真页查原编号显示「已撤销」** ③ 记录可追溯
- [ ] **每日对账差异 = 0**（连跑 2 天，含退款场景）
- [ ] 订单可导出 CSV，可按学员 / 课程 / 时间 / 状态检索
- [ ] 配置页**看不到任何密钥值**（只有"已配置 / 未配置"）
- [ ] 日志 / 埋点 / 响应体**无完整手机号与身份证号**（`scan-sensitive.sh` 通过）
- [ ] **渠道切换演练**：从沙箱切生产只用改配置（**不改代码**），演练留记录

## 七、排期与关键路径

| 步骤 | 内容 | 依赖 |
|---|---|---|
| 1 | 提交商户号申请（两个渠道并行） | **资质 1~5 项** |
| 2 | 沙箱开发：下单 / 回调 / 查单 / 对账 / 退款 | 无（**可先干**） |
| 3 | 资质下号 → 换生产密钥与证书 → 联调真实小额支付 | 步骤 1 |
| 4 | 对账跑通 2 个自然日（差异 0） | 步骤 3 |
| 5 | 退款与撤证联动压测（含已发证特批路径） | 步骤 3 · M3 证书台账 |
| 6 | 上线前检查清单过一遍（PRD §12.5） | 全部 |

- **关键路径 = 步骤 1**（外部审批，不可压缩）。**技术侧从步骤 2 开始，不要等**。
- **M2 与 M3 的关系**：**退款撤证联动**依赖 M3 的证书台账；若 M2 先上线，
  该路径先**只撤权益**，并在台账就绪后**补齐撤证**（同一接口，不另起流程）。
