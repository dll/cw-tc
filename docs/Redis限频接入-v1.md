# Redis 共享限频接入手册 v1.0

> 目标：**多实例部署时，IP 限频不再各算各的**。未配置 Redis 或 Redis 故障时自动降级为进程内限频，服务不中断，但只能保护本实例。

## 1. 适用范围

以下接口按「路由 + 客户端 IP」共享计数：

| 接口 | 上限 | 窗口 |
|---|---|---|
| `POST /api/v1/auth/sms/send` | 20 次 | 1 小时 |
| `POST /api/v1/auth/login` | 20 次 | 1 分钟 |
| `POST /api/v1/auth/sms-login` | 20 次 | 1 分钟 |
| `POST /api/v1/promo/validate` | 20 次 | 1 分钟 |
| `GET /api/v1/verify/:certNo` | 20 次 | 1 分钟 |

> 单手机号每日短信上限、60 秒冷却仍由业务层控制，与 IP 限频叠加生效。

## 2. 服务器配置

在 `/opt/cw-tc/shared/.env` 增加（值按实际环境填写）：

```dotenv
CWTC_REDIS_ADDR=127.0.0.1:6379
CWTC_REDIS_PASSWORD=
CWTC_REDIS_DB=0
```

- `CWTC_REDIS_ADDR` 为空 = 不启用 Redis，使用单实例内存限频；
- 生产建议 Redis 与后端同 VPC、内网访问，**不要暴露公网 6379**；
- 密码写入 `shared/.env`（`chmod 600`），**不得提交到版本库**；
- 多实例必须指向**同一个** Redis 实例 / 集群，否则仍然各算各的。

重启后端后查看日志：

- 成功：无 Redis 告警；
- 失败：出现 `Redis 连接失败，限频降级为进程内`，此时按第 5 节排查。

## 3. 实现方式

- 每次请求执行原子 Lua：`INCR key`，首次计数时 `PEXPIRE window`；
- key 形如 `cwtc:ratelimit:<路由>|<客户端IP>`；
- 计数超过上限返回 `429`，并带 `Retry-After`；
- 固定窗口从首次请求开始计时，窗口结束后自动重置；
- 降级顺序：**Redis → 进程内内存**；Redis 超时/断连不会导致接口 5xx。

## 4. 验证清单

1. 配置 Redis 后重启，确认日志无降级告警；
2. 同一 IP 连续请求登录接口，第 21 次返回 `429`；
3. 若有两个后端实例，分别请求同一接口，**合计第 21 次即被拒**（证明共享计数）；
4. 手动停掉 Redis，再请求：接口仍可用且第 21 次返回 `429`（本实例兜底）；
5. 恢复 Redis 后无需重启，下一请求自动回到共享计数。

## 5. 常见问题

| 现象 | 排查 |
|---|---|
| 一直降级 | 地址/端口不通、防火墙、密码错误、`CWTC_REDIS_DB` 越界 |
| 多实例仍然各放行 20 次 | 实例连的不是同一个 Redis，或部分实例未配置 `CWTC_REDIS_ADDR` |
| 计数不重置 | Redis 时间/逐出策略异常；检查是否被 `maxmemory-policy` 提前逐出 |
| Redis 内存增长 | key 均带 TTL；检查是否被大量伪造 IP 刷出大量短生命周期 key，必要时在网关层先限连 |

## 6. 边界

- 本方案只解决**多实例共享计数**，不替代 WAF / 网关限流；
- Redis 故障期间降级为单实例限频，**总配额会按实例数放大**，属于可用性优先的取舍；
- 短信费用日额度、单号日上限等业务限额仍在数据库/业务层，不依赖 Redis。
