## 1. 第三课堂是什么

### 1.1 三个课堂的由来

| | 第一课堂 | 第二课堂 | **第三课堂（本产品）** |
|---|---|---|---|
| 形态 | 线下、传统课堂 | 学校开设的第二课堂 | **在线、AI 驱动** |
| 组织者 | 任课教师 | 学校 / 团委 / 社团 | **平台 + AI + 教师** |
| 激励 | 学业成绩、学分 | 学分、综测 | **企业认证证书** |
| 时空 | 固定（课表） | 半固定（活动排期） | **完全自主（随时随刻）** |
| 进度 | 统一 | 统一 | **自适应、自定进度** |
| 内容来源 | 教师讲授 | 学校组织 | **AI 生成 + 教师审定 + 机器验真** |
| 评价 | 教师主观 + 期末考 | 参与记录 | **即测即评（机器判分 + 人工采点）** |
| 证书 | 无 | 无（记学分） | **畅网智能科技颁发，编号可验真** |
| **成本** | 学费 | 免费 | **按课程付费解锁（v2 新增）** |
| **陪学** | 教师答疑 | 无 | **AI 实时交互答疑（v2 新增）** |

**它不是"把线下课录成视频放到网上"**，而是四件事的重新组合：

1. **把"教"交给 AI 与课程资产**（教师从"讲授者"变成"审定者"）；
2. **把"学"交还学生**（自选课程、自定节奏、自定深度）；
3. **把"问"交给 AI**（随时可问、有据可查、越问越深）；
4. **把"证"接入产业**（不是学校发的学分，而是**企业发的、行业认的能力认证**）。

### 1.2 官方定义（用于对外）

> **第三课堂**是畅网智能科技推出的、以 AI 为引擎的自主学习教育平台。
> 它由 **AI 生成并维护课程内容**，学生以**手机号注册登录、身份证号实名**、**自主选择典型课程**、
> **付费解锁后在线学习并完成分级测评**，全程可**与 AI 实时交互答疑**并**导出学习笔记**；
> 通过后由 **畅网智能科技有限公司颁发能力认证证书**，证书编号公开可验真。

### 1.3 三个关键取向

**① 以典型课程为主，其它讲座为辅**

- **典型课程（主线）**：体系完整、有实验、有真机实测数据的课程。学生沿"讲 → 练 → 问 → 测 → 证"走完整条路。
  当前：**03-CF（C 语言，15 讲）· 05-OS（操作系统，22 讲）· 07-CN（计算机网络，17 讲）·
  06-CP（编译原理，16 讲）· 08-CC（计算机组成原理，16 讲）· 04-DB（数据库，10 讲）**。
- **讲座 / 专题（辅线）**：单点知识、案例复盘、行业视角。不单独发证，可作主线补充。
  当前：**02-DO（软件工程 · DevOps 案例课，10 单元）**。
- **一个学生可以只走一条主线拿一张证，也可以横向跨课凑齐多张证。**

**② 付费解锁，不做免费全开放（v2 新增）**

- 付费是**商业闭环**，也是**质量承诺**：收费意味着对内容与证书负责。
- 但**付费前必须能看清**：课程详情、讲次大纲、三档证书说明、价格全部公开可查；
  未付费可浏览与试学（试学讲次由管理员配置），**付费后才解锁学习与测评**。

**③ AI 是陪学，不是代考（v2 新增）**

- AI 的作用是**答疑、追问、补基础、联系统**，不是给答案。
- AI 回答**必须给出来源**（讲次 / 讲义文件 / 冻结输出），**说不上来就明说**。
- **测评期间 AI 关闭**（防作弊），交卷后可用 AI 复盘错题。

## 2. 第三课堂的十大特色

> 这十条是"为什么要有第三课堂"的答案，也是后面所有功能需求的**来源**。
> 每条给出：**是什么 → 凭什么成立 → 落到产品上是什么功能**。

### 特色一：**AI 是引擎，不是噱头**

- **是什么**：课程内容、练习题、解析、判分规则由 AI 大规模生成，**但关键判据由人拍板**；
  v2 起，AI 进一步成为**学生的实时陪学**（§7.5）。
- **凭什么成立**：上游 8 门课程已跑通"**AI 起草 → 人定判据 → 机器验真**"的流水线，
  累计产出 **19 份 AI 草稿 / 3827 行**，其中**主动留空 27 个常数等人工填写**。
- **产品功能**：内容后台的"AI 草稿区"（原始稿与人工稿并存可对照）、每条内容的"来源标注"、
  **学生端 AI 助教（回答必附出处）**。

### 特色二：**数字必须真、口径必须写明**

- **是什么**：平台展示的每个数字都必须能追到出处；范围优于单点；测不出的**标【未取到】**。
- **凭什么成立**：上游课程有四类数字标注（【实测】【真机读数】【协议常数】【他方实现】），
  且有 `_range.py` 报范围、`_verify.py` 判据、冻结输出文件可逐字核对；题库 **1204 道题**的参考答案均可溯源。
- **产品功能**：内容区强制"证据链"字段（数字 → 出处 → 类别）；测评解析保留"口径说明"；
  **AI 助教的每条回答都带引用**，无据不答。

### 特色三：**即测即评，客观题机器判**

- **是什么**：学完就测，单选/判断/填空**当场出分**；主观题给"待人工阅卷"清单。
- **凭什么成立**：7 门课都配了 **`_grade.py` 自动判分程序**，**523 道客观题**可自动判分，
  且**每门都能自检满分**（02-DO 114 · 03-CF 130 · 04-DB 47 · 05-OS 54 · 06-CP 56 · 07-CN 63 · 08-CC 59）。
- **产品功能**：在线答题 → 客观题实时判分 → 主观题进入采点队列；**填空标为"半自动"**（宽松匹配，必须抽查）。

### 特色四：**分级测评，能力可分层**

- **是什么**：每门课三档 —— **L1 通识 / L2 工程师 / L3 架构师**，对应三张不同的证书。
- **凭什么成立**：题库已按 L1/L2/L3 组织，**合格线统一**
  （L1 60/75/90 · L2 70/82/92 · L3 80/90/96），且每档题型不同。
- **产品功能**：学生可**逐级考**（推荐）或**跳级考**（需满足前置）；成绩单按档记档。

### 特色五：**企业颁发、编号可验真的证书**

- **是什么**：通过测评 → 生成正式证书（PDF）→ 编号可公开查真。
- **凭什么成立**：编号规则 `CW-{课程码}-{级别位}{年份}{流水号6位}`（例 `CW-CN-M202600137`），
  7 门课各有**三档空白模板 + 合订预览 + 虚构样例**，且**布局校验全过**。
- **产品功能**：自动判证 → 生成 PDF → 分配编号 → 写入"证书台账" → **公开验真页**。

### 特色六：**实名制，身份与证书绑定**

- **是什么**：学生用**手机号注册登录**、以**身份证号完成实名**，证书与真实身份绑定，
  **一生一号一证**（同课同级不重复颁发）。
- **凭什么成立**：证书上本就印有身份证号；上游 `保密说明.md` 已明确**默认脱敏**（前 6 + 8★ + 后 4）。
- **产品功能**：注册即做**平台认证**（格式 + 校验位，**不接三方核验**），
  **手机号与身份证号各司其职**（§7.1 A-0），并**如实披露认证口径**（§9.5）；
  证书默认脱敏打印；**详见 §9**（身份证号不落明文，验证码接口防刷见 §9.6）。

### 特色七：**多课程矩阵，按专业找课**（v2 强化）

- **是什么**：7 门课形成矩阵 —— **竖着走**是一门课由浅到深（L1→L3），**横着走**是多门课各拿一张证；
  v2 起课程**按专业分类**，学生按自己的专业找课。
- **凭什么成立**：课程资产已统一（见 §6），题库 schema、证书命名、合格线全部一致。
- **产品功能**：课程广场（**按专业 / 主线辅线筛选**）、个人"能力地图"。

### 特色八：**自主学习，路径自己拼**

- **是什么**：没有课表、没有排期。学生自定"学哪门、学到哪一级、什么时候考"。
- **凭什么成立**：每讲资源自足（课件 / 讲义 / 口播稿 / 配音 / 实验 / 冻结输出 / 思考题），
  且平台提供**可选的推荐路径**（不是强制进度条）。
- **产品功能**：学习路径推荐、断点续学、错题本、**可选**的每日目标。

### 特色九：**资源即资产，全部可核对**

- **是什么**：每个数字、每段结论都能对到一份**冻结输出文件**（真机跑出来的）。
- **凭什么成立**：以 07-CN 为例，讲级资源含 **25 份课件 / 118 份 Markdown / 133 个代码文件 /
  45 份冻结输出 / 374 条配音**；全平台合计 **1204 题 / 7916 分**。
- **产品功能**：内容详情页可"查看原始输出"；
  v2 起这些资产**同时是 AI 知识库的语料**（§7.5.2）——问得到、也查得到。

### 特色十：**可交接、可复现、可持续**

- **是什么**：AI 生成的内容不是黑箱 —— 换个人接手，能跑、能改、能重制。
- **凭什么成立**：上游全部课程都有"**生产管线交接手册**"、`_ai_draft/` 原始稿一字未改、
  每讲有使用说明 / 思考题 / 接续说明，且**资源体检工具**（`_audit_resources.py`）证明 7 门课资源全部备齐。
- **产品功能**：后台"内容体检"面板（资源齐备度、题库一致性、证书模板完整性、**知识库构建状态**一键自检）。

## 3. 目标用户与权限

### 3.1 角色（**v2 确立为三角色**）

| 角色 | 是谁 | 核心诉求 | 主要动作 |
|---|---|---|---|
| **学员** | 在校生、自学者、转行者 | 学到真东西、随时能问、拿到能证明的证书 | 注册 → 选购 → 学习 → 问 AI → 测 → 领证 |
| **教师** | 高校教师、教研人员 | 自己开课、看懂学情、批好主观题 | 新建课程、维护内容、阅卷、看学情 |
| **管理员** | 刘老师 / 运营 | 管课、管价、管证、管人、发通知 | 课程设置、上架、定价、广播、发证、退款 |

> **角色归并说明（v1 → v2）**：v1 中的「助教 / 阅卷人」**归入教师**（可按课程授权阅卷）；
> 「课程管理者」与「系统管理员」**归入管理员**。
>
> **管理员再分两级（v2.5 新增，见 §7.10.5）**：**超级管理员（super）** 与 **运营管理员（ops）**。
> 纯"只阅卷不建课"的助教角色，通过**按课程授权**实现（`teacher_course_grant`），不单设角色。
>
> ⚠️ **三个角色都不是"会员等级"**：学员 / 教师 / 管理员是**互斥的身份类型**，
> **不由付费升级产生**（付费只解锁课程，不改变身份）。这条不写清，容易被误解成"买课就成会员"。

## 5. 产品目标与成功指标

### 5.1 目标（v2.6）

1. **跑通商业闭环**：一个学生，从注册 → 付费 → 学习 → 测评 → 领证，**全流程无人工介入**（客观题路径）。

3. **AI 陪学可用**：学生能就任意讲次提问，**回答带出处**，且不越出课程范围。
4. **证书可信**：编号唯一、可验真、可撤销。
5. **接入公司站点**：作为 CCIT 官网的平台入口之一对外可见（§7.12）。
6. **可上线**：部署到 `cw-tc.ccit-agent.cn`，可被真实学生使用。

## 7. 功能需求（模块级）

> 标记：`[P0]` 首发必须 · `[P1]` 首发后补 · `[P2]` 远期。每条给出**可测的验收标准**。

### 7.1 账号与实名（模块 A）—— **v2 重构 / v2.1 调整账号口径**

#### A-0 `[P0]` 账号口径（**v2.1 定案，一句话说清**）

| 用途 | 用什么 | 约束 |
|---|---|---|
| **登录账号（主）** | **手机号** | 全局唯一；换绑需双向验证（A-3） |
| **实名与证书绑定** | **身份证号** | 全局唯一（哈希去重）；**终生不改**；不用于登录 |
| 通知 / 找回 / 客服定位 | **手机号** | 同登录账号 |
| ~~学号~~ | **不采用** | 跨校不通用、可能变更、非本人可控标识（A-5） |

> **为什么要两个都用**：手机号**适合作账号**（微信 / 支付宝生态绑定紧、可收发验证码、可换绑），
> 身份证号**适合做实名与证书**（一生一号一证、证书上要印）。
> **两个都采集，各司其职**，而不是让身份证号去兼任登录账号。

#### A-1 `[P0]` 实名注册（**第三课堂平台认证**，v2.3 定案）

> **认证口径（刘老师 2026-10-03 拍板）**：**不接三方实名核验**（不走公安联网核验），
> 采用**第三课堂平台认证** —— 学员**自行申报**（姓名 + 身份证号），**平台留档备查**。
> 因此**证书与页面文案必须如实标注**，不得暗示经过官方核验（见 §9.5）。

- **收集范围以上游为准（不得多收）**：上游 `证书数据.json` 的 `identity_fields`
  **只定义两项 —— 「姓名」「身份证号」**。本平台**只收集这两项**，
  不额外采集学历、工作证明、照片、住址等（最小必要原则，上游 `rationale` 同此口径）。
- **输入**：真实姓名 + **手机号** + 短信验证码 + 密码 + **身份证号**。
- **学员须自行核对**：注册时明示"所填姓名与身份证号将**印在证书上**且**不可自行修改**"，
  要求学员**确认无误后再提交**（改错走人工申诉，见 A-3）。
- **处理**：
  1. **手机号**：格式校验 + 短信验证码（即完成"号码可用"验证）→ **作为登录账号**，**唯一约束**；
  2. **身份证号**：**格式 + 校验位校验**（GB 11643-1999 加权校验，本地可算，不依赖第三方）；
     入库前算 `id_card_hash = HMAC-SHA256(身份证号, 服务端密钥)` 作**唯一索引**，
     并以 **AES-256-GCM 密文**留存（仅供制证时解密，见 §9.2）；
     **明文一律不落库、不进日志**；
  3. **姓名**：格式校验；
  4. 密码强度校验（8–20 位，含字母 + 数字；弱口令库拦截；**不得使用身份证后 6 位或生日**）；
  5. 生成**学员号**（如 `TC2026-000137`，**平台内部编号**，不可改，**不是账号**）；
  6. 记录**同意条款**（用户协议 / 隐私政策 / **付费与退款政策**）的时间戳与版本号。
- **验收**：非法身份证（校验位错）被拒；**同一手机号不允许重复注册**；
  **同一身份证号也不允许重复注册**（防一人多号）；注册成功后可立即登录；
  **任何接口与日志都不得返回明文身份证号**；**收集字段严格等于两项身份字段**（有单测守门）。

#### A-2 `[P0]` 登录（**手机号为主**）

- **方式**：
  - **手机号 + 短信验证码**（默认，最常用，与支付/找回同一套号码）；
  - **手机号 + 密码**（可选，适合常用设备）。
- **防护**：
  - 登录页**强制图形 / 滑块验证码**；
  - 连续失败 5 次锁定 10 分钟（**按账号 + 按 IP 双维度**）；
  - **登录请求走 HTTPS POST body**，手机号与身份证号都**不进 URL / query / Referer**；
  - 异地 / 新设备登录触发**短信 + 站内告警**。
- **验收**：错码锁定生效；登录态有效期 ≤ 7 天；支持"登出全部设备"；
  **日志全文检索无明文身份证号**（由 `deploy/scripts/scan-sensitive.sh` 门禁）。

#### A-3 `[P0]` 找回、改密与换绑手机号

- **找回密码**：手机号短信验证 → 重置密码。
  **不暴露"该手机号是否已注册"**（统一话术"若该号码已注册，短信已发送"），防账号枚举。
- **换绑手机号**：**旧号验证 + 新号验证**双重确认 → 换绑；换绑后旧号立即失效。
  **换绑不影响**：证书、订单、学习权益、笔记（这些都挂在**身份证号 / 学员号**上，不挂在手机号上）。
- **可改**：密码、手机号（走换绑）。**不可改**：姓名、身份证号 —— 需走**人工申诉**（防冒用）。

#### A-4 `[P1]` 注销与数据删除

- 证书依法留存（编号台账），**身份信息可匿名化**，需人工审核（沿用 v1 §9.4）。

#### A-5 `[P0]` **不采用学号**（v2.1 明确排除）

- **学号不作为**：登录账号、唯一标识、证书编号组成部分。
- **理由**：跨校不通用；在校期间可能变更；学号由学校分配、**非本人可控**，
  不适合作为"一生一号一证"的锚点。
- **替代**：对外标识用手机号（登录）+ 学员号（平台内部）；实名锚点用身份证号。
- **验收**：数据库中**不存在**以学号为主键 / 唯一键的表或字段。

#### B-1 `[P0]` 课程广场

- **验收**：课程列表与上游一致；新增课程只需更新上游 JSON + 资源 + **管理员设专业与价格**，**不改前端代码**。

#### B-2 `[P0]` 课程详情与讲次导航

- **展示**：课程简介、**所属专业**、**价格与购买按钮**、三档证书说明、讲次列表（可展开）。
- **每讲**：标题、资源清单（课件 / 讲义 / 视频 / 音频 / 实验 / 冻结输出 / 思考题）。
- **试学**：管理员可为课程配置**免费试学讲次**（默认 0 讲），未付费可看。
- **验收**：**未拥有的资源（如某课无视频）不显示空位**；
  未付费时讲次内容区显示"**付费后解锁**"而非空白。

#### B-3 `[P0]` 专业分类（**平台自管，见 §6.4**）

- **专业字典**：管理员可新增 / 改名 / 停用专业；停用**不影响**已挂课程。
- **课程挂专业**：一门课挂**一个**专业（单选）。
- **建议初始专业**（**平台建议、待管理员确认，非上游数据**）：
  计算机科学与技术 / 软件工程 / 网络工程 / 数据科学与大数据技术。
- **验收**：课程广场按专业筛选结果与后台配置一致；专业改名后**前台同步更新**。

#### B-4 `[P0]` 资源查看器

- **HTML 课件**：**App 端必须走 WebView**（`flutter_inappwebview`），Web 端走 iframe。
  原生渲染无法还原课件的动画与节拍，**这是硬约束**。
- **Markdown**：渲染为网页（代码高亮、表格）。
- **音频/视频**：App 端原生播放器（倍速、断点、后台播放）；Web 端浏览器播放器。
- **冻结输出**：等宽渲染，**保留原始换行**（数字可对账）。
- **验收**：大文件（>10 MB 的 HTML）不卡死；播放位置可记忆；
  **跨端口径 —— 正文与数字必须一致，表现允许有差异**。

#### B-5 `[P0]` 我的课程 / 断点续学

- 已解锁课程进"我的课程"；进度以"讲"为最小单位；换设备登录进度**不丢**（服务端存储）。

#### B-6 `[P1]` 学习路径推荐、错题本

- 推荐为**建议**而非强制；错题自动进错题本。

#### B-7 `[P0]` 课程来源与课程码（**v2.3 新增，修 §8.3 的矛盾**）

- **两类来源，分开管理**：
  | `source` | 谁创建 | 事实源 | 内容同步 | 证书三档默认值 |
  |---|---|---|---|---|
  | **`upstream`** | 上游 `AI化教学创新/` | **上游** | 只读同步（`sync` 覆盖） | 来自上游 `证书数据.json` |
  | **`platform`** | 教师 / 管理员在平台创建 | **平台**（创建者负责） | 不参与 `sync` | **必须自定**（无默认值） |
- **课程码**：两类课程都持有**全局唯一课程码**（上游沿用 `03-CF` 等既有码；
  `platform` 课由平台自动分配，建议形态 `TC-XXXX`），**一经分配即冻结**。
  > 课程码是证书编号 `CW-{课程码}-…` 的组成部分 —— **没有课程码就发不出证书**，
  > 所以它在**课程创建时**分配，不是上架时才给。
- **验收**：课程码全局唯一（数据库唯一约束）；`platform` 课程的证书三档名称与合格线
  **非空**才能上架；`sync` 只覆盖 `upstream` 课程，**绝不动 `platform` 课程**。

### 7.3 支付与订单（模块 G）—— **v2 全新增**

> **原则**：**付费前看得清，付费后学得稳，退款有章可循。**

#### G-1 `[P0]` 课程定价

- **定价主体**：**管理员**（§7.10.2）。
- **模型（v2 取值）**：**按课程整门定价** —— 一个价格解锁该课程的**全部讲次与 L1/L2/L3 三级学习与测评**。
  按等级分别定价列为**可选扩展**（§16-13）。
- **单位与展示**：人民币**元**；支持"原价 / 现价"（活动用，可选）。
- **免费课程**：价格设为 0 即免费，下单流程跳过支付直接开通。
- **验收**：改价**只影响新订单**，不影响已支付订单与既有权益。

#### G-2 `[P0]` 下单与扫码支付

- **流程**：课程详情 → 点"购买" → 创建订单（**快照课程名与当时价格**）→
  展示**支付二维码** → 用户扫码 → 支付结果确认 → **开通权益** → 站内通知。
- **支付方式（v2 取值）**：
  - **Web 端**：**微信支付 Native（扫码）** + **支付宝当面付（扫码）**；
  - **App 端**：调起 **微信支付 / 支付宝** SDK。
  - 最终渠道组合见 §16-12（建议两个都上，互为兜底）。
- **下单幂等（v2.3 新增，防重复付款）**：
  - **同一学员 + 同一课程**若已存在「**待支付**」订单 → **直接复用该订单**（返回同一 `order_no`），
    **不再新建**；数据库以**部分唯一索引**保证
    （`UNIQUE(student_id, course_code) WHERE status='待支付'`）；
  - 客户端下单请求携带 **`request_id`**（幂等键），服务端去重；
  - **失效**：待支付订单超时（默认 **30 分钟**）自动关闭，之后可重新下单。
  - **理由**：学生连点两次"购买"、或弱网重试，若不幂等就会生成两笔订单，
    可能出现**一次课程付两次钱** —— 这是直接的资金问题，必须在数据库层拦住，
    不能只靠前端禁用按钮。
- **结果确认双通道**：**支付渠道异步回调（主）** + **前端轮询订单状态（辅）**；
  两者都必须**幂等**（同一订单重复回调只生效一次）。
- **验收**：支付成功后 ≤ 3 s 内权益生效；订单与回调均有完整日志；
  回调**验签失败一律拒绝并告警**；
  **连点/重试下单只产生一笔待支付订单**（有并发单测）。

#### G-3 `[P0]` 订单与对账

- **订单状态**：待支付 / 已支付 / 已关闭 / 已退款。
- **对账**：每日与支付渠道对账（笔数、金额），**差异必须为 0**，异常触发告警。
- **验收**：订单可导出 CSV；可按学员 / 课程 / 时间 / 状态检索。

#### G-4 `[P0]` 退款 → **连带撤销证书**（v2.2 决策）· **退款窗口见下**（v2.3）

- **退款窗口（v2.3 定案）**：
  | 时机 | 谁能退 | 说明 |
  |---|---|---|
  | **未参加测评**（已付费、未考） | **学员可自助退** | 7 日内自助；超 7 日转管理员处理 |
  | **已参加测评、未发证** | **学员可自助退** | 未取得证书，退款无连带影响 |
  | **已发证** | **仅管理员特批** | 一旦退款即**连带撤销证书**（下条），损失可见，故不给自助 |
  - **理由**：把"可自助"限定在**发证之前**，与"退款即撤证"配套就自洽了 ——
    学员不会因为点了退款而在不知情的情况下丢掉证书。
- **发起**：管理员在订单页发起**全额退款**（部分退款为 P1）；学员自助退为 P0 新增。
- **联动（三件事同一流程完成）**：
  1. **撤销该订单对应的学习权益** —— 学员回到该课程的"未解锁"状态；
  2. **撤销该课程已签发的证书**（若已签发）—— 证书状态置为「**已撤销**」，
     撤销原因记为「**订单已退款**」，写入证书台账；**原编号不可重新分配**；
  3. **保留**订单、支付流水、退款记录与证书台账条目 —— **只标记状态，不删除**。
- **理由（刘老师 2026-10-03 拍板）**：**"退款就把证书取消掉，这个才合理。"**
  退款意味着这门课**并未真正获得**，证书因此失去成立的**前提**。
  这与"证书证明能力"不矛盾 —— 证书证明的前提，是**通过正规付费路径取得的学习资格**。
- **退款后重新购买**：该学员可**再次购买**同一课程；
  若再次通过测评，**重新发证（分配新编号）**；
  旧编号**永久保持「已撤销」**（不复活、不复用）。
- **验收**：退款后 ① 课程回到"未解锁"；
  ② **验真页查原编号显示「已撤销」**；
  ③ 退款与撤销记录均可追溯；
  ④ 渠道退款失败**有重试与告警**；
  ⑤ **不得出现"退了款、证书仍有效"的中间态** —— 两步须在同一业务操作内完成，
  失败则整体回滚并告警。

#### G-5 `[P1]` 发票 / 收据

- 开票需求见 §16-16。

### 7.5 AI 助教与课程知识库（模块 H）—— **v2 全新增**

> **一句话**：**AI 只答这门课，而且必须说明依据。**

#### H-1 `[P0]` AI 实时交互答疑

- **入口**：学习页随时唤起；可"针对当前讲次提问"或"针对当前题目提问"。
- **形态**：对话式，**流式输出**。
- **回答原则（硬约束）**：
  1. **只基于本课程知识库**（§7.5.2）作答，**每条回答必须附来源**
     （讲次 / 讲义文件 / 冻结输出），来源可点开跳转到对应资源；
  2. **无依据就明说**"这门课的资料里没有这条"，**不编**；
  3. **越界拒答**：与课程无关的问题礼貌拒答并引导回课程；
  4. **不给测评答案**：测评进行中 AI 关闭；交卷后可讲解思路，**不给标准答案原文**。
- **上下文**：自动带入"当前课程 + 当前讲次"，支持追问。
- **额度与成本**：按"学员 × 课程"设**每日 / 总提问额度**（管理员可调，§7.10.2）；
  常见问题缓存；模型分级路由（§11.4）。
- **验收**：**带引用比例 100%**（硬门禁）；测评期间 AI 入口强制关闭；额度用尽有明确提示。

#### H-2 `[P0]` 课程知识库生成

- **语料**：上游课程资产的 **Markdown 讲义 / 课件正文 / 冻结输出 / 实验说明**（**只读同步，不改上游**）。
- **构建流程**：同步 → 切片（按讲次 + 标题层级）→ 向量化（Embedding）→ 入向量库 → 建索引。
- **构建主体**：管理员在后台**一键重建**（按课程 / 全量）；与内容 `sync` 联动。
- **可核对**：后台显示**切片数 / 向量数 / 最后构建时间 / 构建耗时**（**数字要有出处**，不写死）。
- **验收**：**不包含**已签发证书、`_ai_draft/` 原始稿等非公开内容；
  重建可重入（重复构建结果一致）；知识库缺失时 AI **明确降级提示**而非胡说。

#### H-3 `[P1]` 知识点检索与关联

- 学生可搜知识点 → 返回对应讲次与讲义片段（复用知识库索引）。

#### H-4 `[P1]` 学情智能摘要

### 7.7 测评与判分（模块 C）

#### C-1 `[P0]` 在线答题

- **前置**：**课程已解锁**（付费或免费）才可参加测评。

#### C-2 `[P0]` 组卷策略（按等级）

| 等级 | 卷面组成（参考上游 README） | 满分 |
|---|---|---|
| L1 | 单选 20 + 判断 10 + 填空 6 + 名解 3 + 简答 6 | 100 |

| L3 | 系统设计 1 + 选型评审 1 + 综合论证 1 + 故障归因 1（+ 跨章综合） | 100 |

#### C-3 `[P0]` 客观题自动判分

- **硬门禁**：上线前必须**移植并跑通 `--self-test`**（标准答案必须满分）。
- **验收**：**填空界面明确标注"半自动，需抽查"**；判分日志可追溯。

#### C-4 `[P0]` 主观题阅卷（采点制）

- **功能**：双人阅卷（差值超阈值触发第三人）、给分备注、批量操作。
- **验收**：采点项与题目的评分要点**逐条对应**。

#### C-5 `[P0]` 成绩与分档

- **验收**：分档计算与 `课程总览.json` 的 `bands` **完全一致**。

#### C-6 `[P1]` 重考与补考

### 7.8 证书（模块 D）

#### D-1 `[P0]` 自动判证

- **触发**：成绩达标 → 自动判定具备发证资格。
- **规则**：同"课程 + 等级"**只发一张**（以最高成绩为准）；跨课可多张。
- **有效期（v2.3 补漏）**：上游 `证书数据.json` 的 `_meta.valid_years = **3**`，
  证书**有效期 3 年**，模板中有「**有效期至**」空字段。因此：
  - 发证时按 **签发日期 + 3 年**计算 `expires_at` 并印在证书上（口径统一，不手填）；
  - **验真页需要区分三种状态**：有效 / **已过期** / 已撤销（不能只报"真实"）；
  - **到期前 30 天提醒学员**（站内信 + 短信），并给出**续证路径**（见 §16-23）。
- **前置校验**：该课程**权益有效**（未退款）。
- **反向联动**：证书签发后若该课程发生**退款** → 按 **G-4 连带撤销**该证书。

#### D-2 `[P0]` 证书生成与颁发

- **生成**：复用上游 `_make_certs.py`（HTML 模板 + headless 浏览器 → PDF）。
- **填充字段严格对齐上游 `blank_fields`（不得增减）**：
  | 字段 | 来源 |
  |---|---|
  | 姓名 | 学员申报（§7.1 A-1） |
  | 身份证号（**默认脱敏**） | 学员申报；脱敏规则见 §9.2 |
  | 考试日期 | 测评记录 |
  | 成绩 | 成绩单 |
  | 证书编号 | 按编号规则生成 |
  | 签发日期 | 签发时刻 |
  | **有效期至** | 签发日期 + **3 年**（上游 `valid_years`） |
- **编号**：`CW-{课程码}-{级别位}{年份}{流水号6位}` —— **全局唯一，原子递增**。
  > ⚠️ **课程码必须由平台分配**（含教师自建课程），否则**编不出编号** —— 见 §7.9 J-1 / §8.2。
- **印全号**：默认脱敏；印全号需**管理员显式勾选**并写审计
  （上游以 `CERT_ID_MODE=full` 控制，平台等价为管理员开关，见 §16-3）。
- **主体**：**管理员**可代发（如线下考试补录）。
- **验收**：编号不重复；PDF 生成失败可重试且**不消耗编号**（事务保证）；
  **「有效期至」= 签发日期 + 3 年**，且有单测。

#### D-3 `[P0]` 证书台账

- 记录：编号、学员、课程、等级、成绩、签发时间、**状态（有效 / 已撤销）**、
  **撤销原因（管理员撤销 / 订单退款）**、撤销时间与操作人。
- **验收**：可导出 CSV；撤销后原编号**不可重新分配**（也不复活）。

#### D-4 `[P0]` 公开验真页

- **入口**：`https://cw-tc.ccit-agent.cn/verify`（**无需登录**，**Go 模板直出**，保 SEO）。
- **输入**：证书编号。
  **输出四态**：**有效**（课程 / 等级 / 姓名脱敏 / 签发日期 / **有效期至**）/
  **已过期** / **已撤销**（含撤销原因类别）/ **不存在**。
- **验收**：**绝不回显完整身份证号**；有防刷限频（按 IP）；
  **已过期的证书不得显示为"有效"**（宁严勿宽）。

#### D-5 `[P0]` 证书下载与分享（**v2.5 由 P1 升为 P0**）

> **为什么升 P0**：学员**付费的核心交付物就是证书**。把"拿到证"定为 P1，
> 等于把产品的最终产物放在次要位置 —— 这与"付费才能学习、通过才发证"的商业闭环不匹配。

- **下载 PDF**（本人，任意端）：私有链接 + 短时 token，**不可枚举**（§9.5）。
- **重新下载**：文件丢失可直接重下，**不消耗编号、不重新签发**（§7.13 L-4）。
- **分享**：分享出去的是 **`/verify?no={编号}` 验真页链接**（公开可查、只含脱敏信息），
  **不是 PDF 本身** —— 避免证书文件被转发冒用。
- **已撤销 / 已过期**：撤销后**不可下载**（§7.13 L-4）；已过期可下载但验真页显示"已过期"。
- **验收**：**重新下载的 PDF 与首次逐字节一致**；分享链接不含姓名全称 / 身份证号 / 手机号；
  **已撤销证书下载入口不可用**。

### 7.9 教师工作台（模块 J）—— **v2 全新增**

#### J-1 `[P0]` 新建课程

- **内容来源（v2.3 关键）**：教师建的课属 **`source = platform`** ——
  **平台即该课程的事实源**，与上游同步课程（`source = upstream`）**分开管理**（§8.3 / §8.4）。
  铁律一「上游是事实源」**只约束 `upstream` 课程**；`platform` 课程的内容由创建者负责。
- **课程码分配（v2.3 新增，硬前置）**：教师提交时由**平台自动分配**一个全局唯一课程码
  （不与上游现有 7 个课程码冲突；建议形态 `TC-XXXX`）。
  **没有课程码就无法生成证书编号**，故课程码在**创建时即分配**，而非上架时才给。
- **输入**：课程名、简介、**所属专业**（选平台专业字典）、目标学员、
  讲次结构（可先列大纲）、资源上传（课件 / 讲义 / 音频 / 代码 / 冻结输出）、
  三档证书目标说明、**三档证书名称与合格线**（`platform` 课无上游默认值，必须自定）。
- **产出**：保存为**草稿**状态，可反复编辑；草稿阶段已持有课程码。
- **提交审核**：填完提交 → 进入**待审核**（J-2）。

#### J-2 `[P0]` 审核与上架（**流程待确认，见 §16-15**）

- **默认流程**：教师提交 → **管理员审核** → 管理员**设价格与专业** → **上架**。
- **理由**：定价与上架是商业动作；上架前需跑一次内容体检（资源齐备度）；
  **`platform` 课程还要核三档证书名称与合格线是否齐备** —— 上游没给它默认值。
- **验收**：未审核的课程对学员**完全不可见**；
  **审核通过后仍不可改课程码**（课程码一经分配即冻结，避免已发证书编号失效）。

#### J-3 `[P0]` 我的课程维护

- 教师可编辑**自己**的课程（内容、讲次、资源）；**不能**改价格与上架状态。
  （内容有问题需下架 → 走 **J-8 申请**，不是自己直接下架。）

#### J-4 `[P0]` 阅卷与本课学情

- 阅卷台（见 C-4）；查看本课程学习人数、测评通过率、错题分布（**聚合数据，不含个人隐私明细**）。

#### J-5 `[P1]` 试题维护

- 教师可为本课程新增 / 修订题目，写入 `question_override`（同步时不覆盖，§8.3）。

#### J-6 `[P0]` 教师可见的数据边界（**v2.5 新增 —— 隐私硬约束，此前完全未定义**）

> **为什么必须写死**：教师既要阅卷（必然要看到学员），又要看学情（不该看到隐私）。
> 边界不写清，实现时最省事的做法就是"把 `student` 表整个查出来给教师看" ——
> 那会把**手机号 + 身份证号**暴露给所有教师。这是本产品最容易发生、后果最严重的越权。

| 教师可见 | 说明 |
|---|---|
| 学员**姓名** | 阅卷与答疑必需（**实名信息，不做二次脱敏**） |
| 学员**学号**（`student_no`） | 平台内部编号，用于定位（**非身份证号**） |
| 学员在本课的**学习 / 测评记录** | 进度、成绩、错题分布（**仅限教师自有课程**） |
| 学员**手机号** | **默认不可见**；如需联系学员，**通过站内信 / 平台消息转发**，不直接给号码 |

| 教师**绝不可见** | 说明 |
|---|---|
| **身份证号（含脱敏）** | 与教学无关，**任何界面、任何接口、任何导出都不返回** |
| **手机号（含脱敏）** | 同上；需要触达学员时走平台转发（见上表末行） |
| **订单 / 支付 / 退款明细** | 商业数据，属管理员（§3.2 权限矩阵） |
| **其他教师的课程与其学情** | 见 J-7 |
| **学员笔记** | 仅本人可见（§7.6） |

- **实现口径（硬要求）**：教师相关接口的响应体**在序列化层就过滤掉**这些字段，
  **不能靠"前端不展示"** —— 前端过滤等于没过滤（抓包即得）。
- **验收**：
  1. 用教师账号遍历全部教师接口，**响应体全文检索无 18 位身份证号、无 11 位手机号**；
  2. 教师查看本课学员列表时，返回字段**不含**身证件号与手机号（**有单测**）；
  3. 教师导出本课学情（若有）**不得包含个人敏感字段**。

#### J-7 `[P0]` 教师之间的数据隔离（**v2.5 新增**）

- **可见范围**：教师只可见 **① 自己创建（`course.teacher_id = 自己`）** 与
  **② 被管理员显式授权**（如"只阅卷不建课"的助教，按课程授权）的课程。
- **不可见**：其他教师的课程、其讲次结构、其题库、其学情、其学员名单。
- **实现**：所有教师端资源的查询**强制带 `teacher_id` 条件**（资源归属校验，§3.2），
  **不允许**"先查全部再过滤"（那是越权漏洞的经典写法）。
- **验收**：教师 A 用自己的 token 请求教师 B 的课程 ID → **必须返回 403，且不泄露该课程是否存在**；
  越权尝试写安全日志。

#### J-8 `[P0]` 下架申请与内容纠错（**v2.5 新增 —— 原来教师遇到内容错误无出口**）

- **问题**：J-3 规定教师不能改上架状态。但内容有错、或教材变更需要停课时，教师**没有任何途径**。
- **解决**：教师可发起 **下架申请**（填原因：内容错误 / 教材变更 / 个人原因 / 其他）→
  进入管理员待办 → **管理员批准后下架**（下架动作仍由管理员执行，商业状态不变）。
- **紧急例外**：**发现严重内容错误**（如答案错误、法条失效）时，教师可**一键申请紧急下架**，
  触发**站内通知管理员**；**在管理员处理前**，该讲次显示"内容核对中"提示，
  **不阻止已购学员继续学习**（避免误伤），但**暂停该课程的新测评发证**直到处理完成。
- **验收**：教师端**无直接下架按钮**；申请后管理员待办可见；
  **紧急下架不删除任何数据**，仅改变展示与发证状态。

#### J-9 `[P0]` 账号停用与课程移交（**v2.5 新增 —— 离职场景此前空白**）

- **停用**：管理员可**停用教师账号**（离职 / 违规），停用后**无法登录**，但**不删除账号与历史数据**。
- **已建课程怎么处理**（必须明确，否则课程会悬空）：
  | 处置 | 说明 |
  |---|---|
  | **移交**（默认） | 管理员将课程**移交给另一位教师**（改 `teacher_id`），课程**继续正常运营**，已购学员无感 |
  | **下架** | 若无人接手，**下架**（已购学员**仍可继续学习与测评**，只是不再对外售卖 —— 与 §7.10.2 改价不改权益同一原则） |
  | **删除** | **不做**。平台课程含已发证书，**不得物理删除**（证书编号要能追溯） |
- **待阅卷怎么办**：停用前**必须清空该教师待阅卷队列**（移交或由管理员代阅），
  否则学员主观题会**永远等不到成绩**。
- **验收**：停用教师后，其课程**必有明确归属**（移交或下架，不会悬空）；
  **无"学员成绩卡在某未归属课程"的情况**。

#### 7.10.5 `[P0]` 管理员分级（**v2.5 新增 —— 此前只有"种子管理员"，没有层级**）

> **为什么必须有**：一个账号能改价、退款、撤证、发广播、开账号 —— 权限过大；
> 且把"开管理员"的能力给所有人，等于没有权限体系。

| 层级 | 能做什么 | 不能做什么 |
|---|---|---|
| **超级管理员（super）** | 全部后台能力 + **创建 / 停用其他管理员** + 系统配置 + 数据导出 | — |
| **运营管理员（ops）** | 课程设置 / 定价 / 上架 / 审核教师课 / 订单与退款 / 证书台账与撤销 / 广播 / 用户管理与开通教师 | **不能**创建或停用管理员 · **不能**改系统配置 · **不能**导出全量数据（需申请） |

- **初始超级管理员**：由**命令行种子**创建（`cw-tc-server seed-admin`，§8.2），
  **首次登录强制改密**；种子命令**幂等**。
- **硬约束**：
  1. **超级管理员数量下限 = 1** —— 不允许把自己降级 / 停用成"零超管"（否则后台永久锁死）；
  2. 每个管理员账号**必须绑定手机号**（找回与异常登录告警）；
  3. **管理员与学员走独立登录入口**（后台独立入口，§9.3）。
- **验收**：ops 调"创建管理员"接口 → **403**；尝试停用最后一个超管 → **被拒并提示**。

#### 7.10.6 `[P0]` 系统配置界面（**v2.5 新增 —— 关键是划清"哪些能进后台"**）

> ⚠️ **本节的中心是一条边界，不是功能清单**：**凭据与密钥绝不进后台**。
> 理由：后台可改 = 可被后台账号（或越权漏洞）取走；且改了密钥会让**历史密文解不开**（§12.2）。

| 分组 | 项目 | 能否后台改 | 说明 |
|---|---|---|---|
| **密钥（只读）** | 身份证加密 / HMAC / 会话密钥、支付与模型密钥 | **只显示"已配置 / 未配置"** | 真实值只走 `/opt/cw-tc/shared/.env`（§12.2）；**后台不展示、不改、不回显任何片段** |
| **渠道非密参数（可改）** | 短信签名与模板 ID、模型名与 Base URL、商户号（非密钥部分） | **可改** | 只改"调用参数"，**不改任何密钥** |
| **业务参数（可改）** | 价格与优惠、免费试学讲次、AI 额度与开关、重考次数、开放等级、广播可退订开关、**退款窗口天数** | **可改** | 改动全部写 `audit_log`，**并与既有权益解耦**（改参数不影响已购） |
| **只读状态** | 各能力可用性（支付 / 短信 / AI 是否已配置并可用）、知识库索引版本与时间 | **只读** | **健康状态不得伪造**（未配置就显示"未启用"） |

- **验收**：
  1. 配置页**全文检索无任何密钥值**（含输入框、隐藏域、接口响应）—— **有单测**；
  2. 未配置某能力时，后台显示**"未启用"**而非报错或伪装可用；
  3. 业务参数变更写审计，且**不回溯影响已购学员**。

#### 7.10.7 `[P0]` 高危操作二次确认与回滚（**v2.5 新增**）

- **高危清单（必须二次确认，且确认内容要写清影响）**：

| 操作 | 二次确认要求 |
|---|---|
| **发起退款** | 显示**金额 + 将连带撤销的证书编号**（若有），要求**输入订单号后 4 位**确认 |
| **撤销证书** | 选择撤销原因 + 显示证书编号 + 提示"**原编号不可恢复、不可重发**" |
| **改价** | 显示**原价 → 新价**；提示"**不影响已购学员**" |
| **下架课程** | 提示"**已购学员仍可学习**"；显示已购人数 |
| **停用账号 / 停用教师** | 教师停用需**先选择课程处置方式**（§7.9 J-9） |
| **广播群发** | 强制预览触达人数（§7.11.2） |

- **可回滚的**：**改价**（改回即可）· **下架**（重新上架，已购学员不受影响）。
- **不可回滚的（必须在确认框里说清）**：**退款**（资金已出）· **撤销证书**（原编号永久作废、
  不可重发）· **删除账号**（§7.1 A-4 的匿名化不可逆）· **广播**（已送达不可撤回，
  故只能靠发送前强制预览拦住 —— 这也是 §7.11.2 要求强制预览的根本原因）。
- **验收**：高危操作**未二次确认不得执行**（**后端也要拦，不能只靠前端弹窗**）；
  每次操作与确认方式写 `audit_log`（含操作人、IP、影响对象）。

#### 7.10.8 `[P1]` 批量操作（**v2.5 新增**）

- **课程批量**：批量上架 / 下架 / 改价（**按绝对值或按比例**）/ 挂专业 / 调排序权重。
- **学员批量**：按筛选条件（专业、课程、状态）**批量发站内通知**（定向触达，不等同广播）。
- **硬约束**：
  1. **批量改价必须预览**"哪些课程、原价 → 新价"，确认后执行；
  2. **逐条成功 / 失败可查**（不能只报"部分失败"而不给明细）；
  3. 批量操作**写 `audit_log`**（一条批次 + 各条明细）。
- **验收**：批量改价 10 门课，**逐条明细可下载**；失败条目**可单独重试**。

#### 7.10.9 `[P0]` 合规数据导出与删除（**v2.5 新增 —— 个人信息可携带权的落地**）

- **背景**：《个人信息保护法》赋予个人**查阅、复制、可携带**其个人信息的权利（§9.4）。
  平台必须能真的做到，而不是只在政策里写一句。
- **三种路径**：

| 谁发起 | 场景 | 实现 |
|---|---|---|
| **学员自助** | 想带走自己的数据 | 个人中心一键导出（§7.13 L-8）：JSON + Markdown 摘要 |
| **管理员代导出** | 学员申诉 / 无法自助（如账号已锁） | 管理员在用户详情页发起，**需二次确认 + 填写事由** |
| **管理员删除（匿名化）** | 学员注销 / 依法删除 | 走 §7.1 A-4：**证书台账留存**，**身份信息匿名化**，**不物理删除** |

- **硬约束**：
  1. **导出内容一律脱敏**（身份证号绝不出现明文；手机号按需脱敏）；
  2. **导出留痕**：谁、何时、为哪个学员、导出了哪些范围 —— **全部写 `audit_log`**；
  3. **导出文件不落公开目录**，用**短时私有链接**下发；
  4. **代导出需超级管理员**（导出全量数据是高风险动作，§7.10.5）。
- **验收**：导出文件**全文检索无 18 位身份证号明文**；
  管理员每导出一次，`audit_log` **必有对应记录**；**删除账号后证书编号仍可按编号验真**。

#### 7.10.10 `[P0]` 用户管理（学员 / 教师 / 管理员）—— **v2.6 全新增**

> **为什么补**：此前"用户管理"在本节表格里打了 ✅，但**全部定义只有一句**
> "学员 / 教师 / 管理员账号、状态、解封"。**列表怎么查、详情能看什么、
> 封号按什么规则、注销谁审、密码怎么重置 —— 一条都没有。**
> 与之前"M0 项目骨架 ✅"是同一类问题：**勾了，但没做**。

**（一）三方对照：谁管谁**

| 能力 | 学员 | 教师 | 管理员 |
|---|---|---|---|
| 列表 / 搜索 / 筛选 | ✅ | ✅ | ✅ |
| 详情页 | ✅（见（二）） | ✅ | ✅ |
| **开通** | 自助注册（§7.1） | **管理员开通**（§8.2） | **仅 super 创建**（§7.10.5） |
| **状态变更** | 停用 / 解封 | 停用（**含课程移交** §7.9 J-9） | 停用（**不能停最后一个超管**） |
| **重置密码** | ✅ 发重置链接 | ✅ 发重置链接 | ✅ 发重置链接 |
| **删除** | **不做物理删除**，走注销匿名化（§7.1 A-4） | 不做 | 不做 |
| **谁能操作** | ops + super | ops + super | **仅 super** |

**（二）学员详情页 —— 管理员可见字段（本节最要紧的部分）**

> 与 §7.9 J-6 的**教师边界是同一条原则**（最小必要），只是管理员范围更宽。
> 但**宽 ≠ 无痕**：凡涉及身份信息，一律"默认脱敏 + 看全号要留痕"。

| 数据 | 可见 | 约束 |
|---|---|---|
| 姓名 / 学号 / 注册时间 / 状态 | ✅ | — |
| **手机号** | ✅ | **默认脱敏**（`138****5678`）；看全号需**填事由**并留痕 |
| **身份证号** | **默认脱敏** | **看全号需 super + 填事由 + 写审计**（与 §7.8 D-2 印全号同口径） |
| 订单 / 支付 / 退款记录 | ✅ | 退款仍走 §7.3 G-4 与 §7.10.7 二次确认 |
| 证书记录 | ✅ | 含撤销原因 |
| 学习 / 测评记录、AI 用量 | ✅ | — |
| **学习笔记** | **❌ 不可见** | 仅本人（§7.6）—— **管理员也不读** |

- **硬要求**：详情页**默认全脱敏**，**不允许"打开即明文"**；
  每一次"查看全号"**都写 `audit_log`**（谁、何时、看的是谁、事由）。
- **理由**：管理员权限大，**不等于可以无痕查看公民身份证号**。
  有留痕才能事后追责；没有留痕，内部泄露查不出人。

**（三）状态与封禁（规则此前完全空白）**

```
正常 ──▶ 临时限制（自动，按 §9.6 限频）──▶ 停用（可解封）──▶ 永久封禁（不可自助恢复）
```

| 触发场景 | 处置 | 谁能执行 |
|---|---|---|
| 短信接口异常刷取 | **临时限制**（自动，按 §9.6 限频） | 系统自动 |
| 异常登录（异地 / 多设备） | 要求二次验证，不改状态 | 系统自动 |
| 测评异常（疑似作弊） | **复核该次成绩**，**不直接封号** | ops |
| 支付异常 / 恶意退款 | **停用**（可解封） | ops |
| **实名不符（冒用他人身份）** | **停用 + 转人工核实** | ops |
| 严重违规（倒卖课程、攻击平台） | **永久封禁** | **super** |

- **封禁必填**：原因类别 + 说明 + 期限（**永久需 super**）；**全部写 `audit_log`**。
- **学员侧必须可见**：被封学员登录时**显示"账号已停用 + 原因类别 + 申诉入口"**
  —— **不允许"莫名登不上"**，否则客服会被问爆，且不合规。
- **申诉**：登录页发起 → 管理员待办 → 结果通知学员（表见 §8.2 `account_appeal`）。
- **解封**：ops 可解封（永久封禁需 super）。**解封不恢复已撤销证书、不恢复已退款订单。**

**（四）重置密码（管理员看不到明文，只能发重置）**

- **管理员永远看不到学员 / 教师的密码**（库里只有 `password_hash`，这是设计前提）。
- **方式**：生成**一次性重置链接**（有效期 30 分钟，校验手机号后 4 位）
  或**短信下发临时密码** → **首次登录强制改密**。
- **必须留痕**（谁、何时、为谁重置）—— 这是"账号被盗"溯源的关键线索。
- **禁止**：管理员**不得**代设密码、**不得**获知新密码。

**（五）注销审核（§7.1 A-4 说"需人工审核"，但谁审、审什么、审完做什么都没写）**

- **审核人**：ops（待办列表）。
- **前置校验**（任一不通过则驳回并说明理由）：
  1. 无**进行中**的订单（待支付已关闭 / 已支付已消费或已退款）；
  2. 无**处理中**的退款；
  3. 已向学员**明确告知**："证书台账依法留存，但身份信息将被匿名化"。
- **执行（不可逆，需二次确认）**：

| 处理 | 对象 |
|---|---|
| **匿名化** | 姓名 → 脱敏占位；手机号 → 置空；`id_card_cipher` 与 `id_card_hash` → **删除** |
| **保留** | 证书台账（编号 / 课程 / 等级 / 成绩 / 签发与撤销时间）、订单与资金流水 |
| **保留** | 该学员证书**仍可按编号验真**（验真页只显示脱敏姓名与状态） |

- **处理时限**：**≤ 15 个工作日**（在隐私政策中明示，§9.7）。
- **验收**：注销后该手机号**可重新注册**；**原编号验真仍返回"有效 / 已撤销"，不返回"不存在"**。

**（六）搜索、筛选与导出（三角色共用）**

- **搜索**：按**手机号 / 姓名 / 学号 / 账号**匹配（精确或前缀）。
  ⚠️ **不允许按身份证号搜索**（**哪怕用哈希也不行** —— 那等于给身份证号开了一个查询接口，
  正是 §9.6 防撞库要堵的口子）。
- **筛选**：状态、注册时间区间、已购课程、专业、是否有证书。
- **分页**：单页上限 **100**（§11.6）。
- **导出**：走 §7.10.9 合规导出（**仅 super**，填事由，留痕），**内容一律脱敏**。

- **验收**：
  1. 三类用户**均可列表 / 搜索 / 筛选 / 查看详情**；
  2. **列表与详情页响应体无明文身份证号与手机号**（**有单测**）；
  3. 重置密码后**旧密码立即失效**，且被重置者**首登强制改密**；
  4. 封禁 / 解封 / 重置 / 注销**每条都有 `audit_log`**；
  5. **被封学员登录能看到原因类别与申诉入口**；
  6. **按身份证号搜索接口不存在**（越权用例：直接调 `/admin/users?id_card=...` → 参数被忽略）。

### 7.13 学员侧「我的」模块（模块 L）—— **v2.5 全新增**

> **为什么补**：§8.1 站点地图里 `/me/orders`、`/me/certs`、`/me/scores` 早就列了路由，
> 但 §7 功能需求里**一条都没有对应的条目** —— 学员点进"我的订单"能做什么，PRD 从未回答。
> 这是"画了菜单没写菜"。

#### L-1 `[P0]` 我的课程

- **分两组展示**：
  - **已解锁**：可点进学习，显示**学习进度**（已学讲数 / 总讲数 + 百分比）；
  - **未解锁**：显示课程卡（含价格与"去购买"），**不泄露讲次内容**（只显示大纲标题）。
- **排序**：最近学习优先；支持按专业 / 状态筛选。
- **验收**：退款后该课程**从"已解锁"移回"未解锁"**（权益撤销的可见结果，与 G-4 一致）；
  进度与学习记录一致（同一讲重复进入不重复计数）。

#### L-2 `[P0]` 我的订单

- **列表**：订单号、课程、金额、状态、下单时间、支付渠道。
- **可操作（按状态）**：
  | 订单状态 | 学员可做 |
  |---|---|
  | **待支付** | **继续支付**（同一订单继续，不新建 —— 见 G-2 幂等）· **取消订单** |
  | **已支付** | 查看详情 · 进入课程 · **申请退款**（**仅限退款窗口内**，见 G-4） |
  | **已关闭**（超时/取消） | 仅查看 |
  | **已退款** | 查看退款时间与到账渠道；**若该课程证书已被撤销，此处明示** |
- **退款进度可见**：申请后显示"退款处理中 / 已退款 / 退款失败（附原因与联系方式）"。
- **验收**：**待支付订单可继续支付且订单号不变**；退款窗口外的"申请退款"按钮**不出现**（不是点了才拒）；
  **退款导致证书撤销时，订单详情必须明示撤销结果**（不能让学员自己去验真页才发现）。

#### L-3 `[P0]` 我的成绩

- **展示**：按课程分组，列出**每一次**测评记录（档位、总分、分档、是否达标、考试时间）。
- **用途**：让学员自己看清"当前可报考哪一档、还差多少分"。
- **验收**：历次成绩**不覆盖**（与 C-6 一致）；**不达标记录也如实展示**（不隐藏失败记录）。

#### L-4 `[P0]` 我的证书

- **展示**：有效 / **即将到期（90 天内）** / **已过期** / **已撤销**（含撤销原因类别）。
- **可操作**：
  - **下载 PDF**（**P0** —— 见 §7.8 D-5 的优先级调整）；
  - **重新下载**：**证书 PDF 丢失时可直接重新下载，不消耗编号、不重新签发**（编号与签发日期不变）；
  - **到期后**：按 §16-25 的续证路径（待定）处理；
  - **已撤销**：**不可下载**，只显示状态与原因（撤销后不得再下发文件）。
- **验收**：重新下载的 PDF 与首次下发**逐字节一致**（同一次签发只对应一份文件）；
  **已撤销证书的下载入口必须不可用**；**证书列表不得显示完整身份证号**。

> ⚠️ **补下载 ≠ 补办**（必须分清，否则会混乱）：
> **补下载** = 文件丢了，平台**重新下发同一份**（编号、签发日期、内容全不变）；
> **补办** = 换发**新编号**（仅"原编号不可用但事实成立"的极端场景，需管理员特批并留痕）。
> **默认只做补下载**；补办列为 P2 或直接不做（见 §16-29）。

#### L-5 `[P0]` 消息中心

- **分类**：
  | 类型 | 内容 | 可关闭 |
  |---|---|---|
  | **系统消息** | 账号安全（登录异常、换绑成功）、政策更新 | **否**（合规必需） |
  | **事务通知** | 支付、退款、出分、发证、审核结果 | 否（但可关短信渠道） |
  | **广播** | 管理员群发（新课上架、活动） | **是**（可退订） |
- **交互**：已读 / 未读、全部已读、点击跳转到目标页；未读数在底部导航有角标。
- **验收**：同一事务通知**不重复发送**（与 §7.11.2 幂等一致）；**退订广播不影响系统消息与事务通知**。

#### L-6 `[P0]` 账号与安全设置

- **可改**：密码（改密需旧密码或短信验证）· 手机号（**换绑需旧号 + 新号双向验证**，见 §7.1 A-3）。
- **不可改**：姓名、身份证号（走人工申诉，见 A-3）。
- **会话管理**：
  - **登录设备列表**（设备、地点、最近活跃时间）；
  - **踢出指定设备** / **登出全部设备**；
- **多设备策略（v2.5 明确，此前只有一句验收）**：
  - **同账号允许同时在线**（学员可能手机 + 电脑一起用，**不做单设备互踢**）；
  - 但**同一设备类型不限制数量**，改密 / 登出全部时**全部会话失效**。
- **注销账号**：入口在账号设置内，走 §7.1 A-4（证书依法留存，身份信息可匿名化，人工审核）。
- **验收**：换绑手机号后**旧号立即不可登录**；登出全部设备后**所有会话在 ≤ 1 分钟内失效**。

#### L-7 `[P1]` AI 额度与用量可见

- 显示**本课程今日剩余提问次数**与额度规则（额度由管理员按课程 / 学员配置，§7.10.2）。
- **理由**：额度用尽却无提示，学员会以为是故障 —— 必须**提前可见**。

#### L-8 `[P0]` 个人信息与数据导出

- **查看**：姓名、手机号（脱敏）、身份证号（**脱敏**）、注册时间。
- **导出个人数据**：学员可**自助导出**自己的数据（账号信息 + 学习记录 + 成绩 + 证书编号 + 笔记），
  格式 **JSON + Markdown 摘要**；见 §7.10.9 与 §9.4（个人信息可携带权）。
- **申诉入口**：改姓名 / 身份证、成绩申诉、退款纠纷，统一在此提交并显示处理状态。
- **验收**：**导出内容不含任何明文身份证号**（导出前脱敏）；
  导出动作**写审计**（谁、何时、导出了什么范围）。

### 8.3 数据来源与同步（**关键设计**）

```
AI化教学创新/课程总览.json            ──sync──▶ course / lecture / question_bank
AI化教学创新/*/测试题集/题库.json      ──sync──▶ question
AI化教学创新/*/测试题集/证书模板/证书数据.json ──sync──▶ 证书元数据（规则/合格线）
AI化教学创新/*/{讲义,课件,冻结输出}    ──sync──▶ 资源 + **知识库语料**（§7.5.2）
```

- **单向同步**：**`source = upstream` 的课程**，内容以上游为**唯一事实源**，平台只读不改
  （写入用"覆盖表"）。
- **重跑即刷新**：上游改题后重跑同步脚本，平台数字自动更新（**不写死**）。
- **冲突处理**：平台对 `upstream` 课程新增 / 修订的题，存入 `question_override`，同步时不覆盖。
- **平台自有数据不参与同步**：`major`、`price_*`、`status`、`entitlement`、`order` 等
  **全部是本平台数据**，上游怎么改都不动它们（这是 §6.4 的落地约束）。
- ⚠️ **`source = platform` 的课程完全不参与 sync（v2.3 修矛盾）**：
  教师 / 管理员在平台建的课**不在上游目录里**，其事实源是**平台自身**。
  **`sync` 必须按 `source` 过滤**，绝不能把 `platform` 课程当成"上游删掉的课"而清空 ——
  这是本节最容易写错、后果最严重的一行。*（v2.2 之前本节写"上游唯一事实源"，
  与 §7.9「教师可建课」直接冲突，v2.3 以 `source` 字段调和。）*

### 8.4 上游字段 vs 平台字段（**边界表，避免混淆**）

| 数据 | 来源 | 上游改动是否影响 |
|---|---|---|
| 课程名 / 讲次 / 资源清单 / 题库 / 合格线 / 证书名（**`upstream` 课程**） | **上游（只读同步）** | ✅ 会刷新 |
| 课程名 / 讲次 / 资源 / 题库 / 合格线 / 证书名（**`platform` 课程**） | **平台自管**（教师创建） | ❌ **完全不影响**（§8.3） |
| **课程码 / 课程来源 `source`** | **平台自管**（分配后冻结） | ❌ 不影响 |
| **专业分类** | **平台自管** | ❌ 不影响 |
| **价格 / 上下架状态 / 排序权重** | **平台自管** | ❌ 不影响 |
| **学习权益 / 订单 / 支付 / 退款** | **平台自管** | ❌ 不影响 |
| **证书有效期（签发 + 3 年）** | 规则来自上游 `valid_years`，**计算在平台** | ✅ 上游改年限则**仅影响新证**，**已发证书的 `expires_at` 不回溯变更** |
| **AI 额度 / 知识库索引** | **平台自管**（语料来自上游） | 语料会刷新，额度不受影响 |

## 9. 安全与合规（**本产品的红线**）

> 本产品采集**身份证号**，属《个人信息保护法》定义的**敏感个人信息**；
> 同时涉及**在线支付**与**生成式 AI**。这一节是**上线的前提**：
> 任一条不满足，都不得对真实学生开放。
>
> **v2.1 口径**：**登录账号是手机号，身份证号只做实名与证书绑定** ——
> 这**降低**了攻击面（手机号不像身份证号那样可被构造枚举），
> 但**新增**了短信验证码接口的防护要求（§9.6）。

### 9.1 数据最小化

| 数据 | 是否采集 | 用途 | 留存 |
|---|---|---|---|
| 姓名 | 是 | 证书署名 | 长期（与证书绑定） |
| **手机号** | **是（必须）** | **登录账号** + 验证码 + 找回 + 通知 + 支付客服定位 | 长期 |
| **身份证号** | **是（必须）** | **实名 + 证书编号绑定**（**不用于登录**） | 长期（**加密 + 哈希，永不存明文**） |
| 出生日期/性别 | **否** | — | **不从身份证号推导存储** |
| 住址 | **否** | — | — |
| **学号** | **否** | — | **明确不采集、不做标识**（§7.1 A-5） |
| **支付信息** | **否（本平台不存卡号）** | 支付由微信 / 支付宝托管 | **不落地任何支付凭据** |

**原则**：能证明"是谁"就够了，不采集、不推算、不存储任何多余信息。

### 9.2 存储要求（硬性）

1. **明文绝不落库**：身份证号入库前以 **AES-256-GCM** 加密（密钥由环境变量 / KMS 注入，**不进代码库**）。
2. **两个唯一约束**：
   - `phone` —— **登录账号**，唯一索引（可换绑，换绑即改此值）；
   - `id_card_hash = HMAC-SHA256(身份证号, 服务端密钥)` —— **实名去重**，唯一索引，
     **不用于登录**；不可逆，泄露也无法还原。
3. **展示一律脱敏**：身份证号默认 `前6位 + ******** + 后4位`（`110101********1234`）；
   手机号默认 `138****5678`。
4. **日志脱敏**：所有日志、错误上报、监控埋点**必须过滤身份证号与手机号**（正则过滤器 + 单测）。
5. **支付凭据**：本平台**不存储**银行卡号、CVC、支付密码；只保存渠道返回的**交易号**。

### 9.3 传输与访问

- **全站 HTTPS**（腾讯云免费证书 + nginx，强制 HSTS）。
- 数据库、缓存**不对公网开放**（安全组只放 80/443/22）。
- 后台接口走**独立鉴权**（管理员 Token + 二次验证），操作全部进 `audit_log`；
  **后台入口与学员入口分离**（不同路径 + 独立会话 Cookie 名，避免会话串用）。
- **教师的数据可见边界（v2.5 新增，见 §7.9 J-6）**：
  教师端接口的响应**在序列化层过滤**身份证号与手机号 —— **不依赖前端隐藏**；
  教师只能触达**自有 / 被授权课程**的数据（§7.9 J-7，资源归属校验）。
- **验真页防刷**：按 IP 限频（如 20 次/分钟），**不回显完整身份证号**。

### 9.4 用户权利（必须实现）

| 权利 | 实现 |
|---|---|
| 知情同意 | 注册时明示"采集什么、做什么用、存多久"，**勾选同意**（版本化留痕） |
| 查询 | 个人中心可看自己的实名信息（脱敏）与全部证书 |
| 更正 | 手机号可自助改；姓名 / 身份证走人工申诉 |
| 删除 | **注销账号**：证书依法留存（编号台账），**身份信息可匿名化**，需人工审核；**处理时限 ≤ 15 个工作日**（v2.6）；流程见 §7.10.10（五） |
| 撤回同意 | 支持，撤回后停止使用相应信息（已发证书仍可按编号验真） |
| **AI 会话** | 学员可**自行删除** AI 会话与笔记；删除后不再作为任何用途 |
| **可携带（v2.5 新增）** | **学员可自助导出**自己的数据（JSON + Markdown 摘要，**导出前脱敏**）；
  无法自助时管理员可**代导出**，一切导出**写审计**（§7.13 L-8 · §7.10.9） |
| **教师的可见边界（v2.5 新增）** | 教师**不可见**学员身份证号与手机号（§7.9 J-6）——
  这是"数据最小必要"对**内部人员**的落地，不只是对外 |

### 9.5 证书颁发的合规边界（**v2.3 平台认证口径**）

- 证书**必须**标明：颁发主体、课程、等级、成绩、编号、**签发日期、有效期至**。
- **不得**暗示"国家认证""官方资格"；证书是**企业能力认证**，非学历、非职业资格。
- ⚠️ **实名口径必须如实披露（v2.3 新增，因不接三方核验）**：
  - 本平台采用**第三课堂平台认证** —— **姓名与身份证号由学员自行申报，平台留档备查**；
  - **不得**声称或暗示"已通过公安联网核验""官方实名认证""已完成身份核验"；
  - 证书页脚 / 验真页 / 注册页须标注一致的说明，例如：
    **「本证书所载身份信息由持证人自行申报，平台已留存申报记录，未接入官方身份核验系统。」**
  - **理由**：不做核验却写成"已核验"，是对第三方的误导 —— 用人单位按证书核人时会出问题。
    如实披露反而保护平台：**平台承诺的是"能力测评"与"留档一致性"，不是"身份真实性"**。
- 已签发证书进**独立台账**；模板与已签发件**不放入公开代码库**。
- **已签发 PDF 的存储要求**（对照上游 `保密说明.md` §三）：
  平台必须能存储与下发证书，因此**不能照搬"用完即销毁"的线下流程**；改为：
  - PDF **加密存储**，**私有下载链接**（带短时 token，不可枚举）；
  - **不进公开目录、不进任何共享盘 / 云同步**；
  - 上游那份"独立保密目录 + 不做云同步"的约束，**在平台侧等价为：访问受控 + 加密 + 链接不可猜**。

### 9.6 ⚠️ **账号与验证码的风险与对策（v2.1 改写）**

**口径变化**：v2.0 曾用**身份证号**作账号，风险是"**身份证号可被构造枚举**"；
v2.1 改回**手机号**作账号，该风险**消失**（手机号不可构造）。
但换来**新的风险面 —— 短信验证码接口**（可被刷、直接产生费用）。**两者都要防**。

| # | 风险 | 对策（**全部强制**） |
|---|---|---|
| 1 | **短信轰炸 / 接口刷量**（**v2.1 新增首要风险**，直接烧钱） | ① 发码前**必须先过图形/滑块验证码**；② **单手机号日上限**（如 10 条/日）；③ **单手机号 60 s 冷却**；④ **单 IP 限频**；⑤ 同号短信内容与间隔做**去重**；⑥ 短信费用**日额度告警** |
| 2 | **手机号撞库**（外部泄露的手机号库） | 登录**强制图形验证码**；失败 5 次锁定（账号 + IP 双维度）；登录接口独立限频 |
| 3 | **弱口令** | 8–20 位含字母 + 数字；**弱口令库拦截**；**禁止身份证后 6 位 / 生日作密码** |
| 4 | **敏感信息泄露于 URL / 日志** | 登录与注册走 **POST body**；手机号、身份证号**禁止**出现在 query、Referer、埋点、错误堆栈；日志正则过滤 + **单测守门** |
| 5 | **凭证被盗后横向** | 敏感操作（**换绑手机号** / 改密 / 注销 / 退款申请）需**短信二次验证** |
| 6 | **一人多号** | `phone` 唯一 + `id_card_hash` 唯一，**双层去重**；注册接口幂等 |
| 7 | **找回接口泄露注册状态** | 统一话术，**不区分**"已注册 / 未注册" |
| 8 | **换绑被劫持** | 换绑需**旧号 + 新号双向验证**；换绑后**通知原手机号**；7 天内**不得二次换绑** |
| 9 | **前端缓存残留** | 登录表单关闭自动填充历史；**不写入 localStorage** |

- **上线门禁**：
  - `deploy/scripts/scan-sensitive.sh` 必须报 **0 命中**（代码 + 日志 + 响应体 + 测试快照）；
  - **渗透自测（登录）**：脚本对登录接口做 100 次无效尝试，验证锁定与限频生效；
  - **渗透自测（短信）**：脚本对发码接口做**超频尝试**，验证图形验证码前置、日上限、冷却均生效。
- **关于支付与手机号的关系（**避免一个常见误解**）**：
  手机号作账号**便于**找回、通知与客服定位；但**微信 / 支付宝的支付回调不携带用户手机号**，
  因此**对账与订单关联一律以「订单号 + 渠道交易号」为准**，
  **不得**用手机号作为支付对账键。

### 9.7 支付合规（v2 新增）

- **资质前提**：微信支付 / 支付宝商户号需**企业资质**（畅网智能科技营业执照、对公账户）；
  **资质未办下来前，支付功能不得上线**（可用"免费课程"模式先跑内容闭环）。
- **必备文本**：**用户协议**、**隐私政策**、**付费与退款政策**，三者均须
  **版本化留痕**（注册时记录同意的版本号与时间；政策升版后对既有用户如何处理见 §16-24）。
  其中**付费与退款政策必须写明**：
  ① **退款窗口**（§7.3 G-4：未参加测评 / 已考未发证可自助退；**已发证仅管理员特批**）；
  ② **"退款后已发证书将被撤销"**（且原编号不可恢复）；
  ③ 退款到账时限与渠道（原路退回）。

- **隐私政策另须写明**（v2.6）：
  ① **账号注销的处理时限（≤ 15 个工作日）**与保留范围（证书台账 / 订单流水依法留存）；
  ② **封禁规则**：什么情况会停用账号、如何申诉；
  ③ **管理员查看身份信息需留痕**（内部审计要求，提升透明度）。
- **不夸大**：课程页不得出现"包过""保过""包就业"等承诺性表述。
- **资金安全**：回调**验签**、金额**二次核对**（订单金额 vs 渠道金额）、**对账差异为 0**。
- **审计**：退款、改价、下架等**资金与商业动作全部留痕**（谁、何时、原值 → 新值）。

### 9.8 AI 合规（v2 新增）

> ⚠️ **前置提醒（v2.3 新增，非技术问题，需外部确认）**：
> 面向公众提供**生成式 AI 问答**，在国内可能涉及**算法备案 / 安全评估**等要求
> （视服务形态与用户规模而定）。**这不是工程能自行判断的事项** ——
> 建议在 **M4 开工前**由法务 / 合规确认是否需备案、以谁的名义备案。
> **在确认之前不要把 AI 答疑对公网全量开放**（可先限定在校内 / 邀请制试运行）。
> 见 §16-25。

| 要求 | 落地 |
|---|---|
| **生成内容标识** | AI 回答区域**显著标注"内容由 AI 生成，仅供参考"**（法规要求） |
| **内容安全** | **输入 + 输出双向审核**（敏感词 / 违规内容过滤），命中即拦截并记日志 |
| **语料合法** | 知识库语料**仅来自自有课程资产**（上游 8 门课，团队自行生产），**不抓取第三方内容** |
| **数据不出境** | 优先选用**国内合规模型服务**；若用境外模型，则**不发送个人信息**（仅课程语料），并评估合规 |
| **可追溯** | 每次调用记录模型、token 数、耗时；**不记录**身份证号 |
| **投诉举报** | 提供对 AI 回答的"举报 / 纠错"入口，管理员可下架问答 |
| **不替代人工** | 证书发放**不依赖 AI 判断**（判分与分档是确定性规则，AI 不参与） |

### 9.9 未成年人

- 本平台面向**高校学生**（一般已成年）。若实际存在未成年学员，
  **需监护人同意**并限制 AI 会话留存 —— **该项待确认，见 §16-18**（如实标注，不假定）。

### 10.1 性能

| 项 | 目标 |
|---|---|
| 首屏（课程广场）· **App 端** | 冷启动 ≤ 2 s（P75，中端安卓机） |
| 首屏（课程广场）· **Web 端** | **待实测后重定** —— Flutter Web 首屏体积大（CanvasKit + 中文字体），**本机未实测，故不设数** |

| **AI 首字返回** | **待实测后重定**（受模型与网络影响大，**不设数**，见 §11.4） |
| **知识库重建（单课）** | **待实测后重定**（与切片量、Embedding 吞吐相关） |
| 证书 PDF 生成 | P95 ≤ 5 s（异步，不阻塞） |
| 静态资源（课件/视频/音频） | 走 CDN（腾讯云 COS + CDN） |
| 并发 | 首发 500 并发在线即可（可横向扩容到 5000） |

### 10.2 可用性与运维

- **部署方式**：沿用 CCIT / cw-vopc 约定 ——
  GitHub Actions → SSH → `/opt/cw-tc/releases/<时间>-<commit>` → `current` 软链 →
  健康检查（`/api/v1/health`）→ **失败自动回滚**；旧版本保留最近 5 个。
- **数据保护**：PostgreSQL 数据存 docker 卷 / 宿主目录，**跨版本部署不丢**；每日自动备份。
- **监控**：健康检查 + 关键接口错误率告警；
  **必须告警的三件事 —— 证书签发失败、支付回调失败、对账差异非 0**。
- **回滚**：任一版本可一键回滚（软链切换，秒级）。

### 10.3 兼容性（**v2 收敛**）

**移动 App 为主端，Web 为辅端，管理后台桌面优先。**

| 端 | 要求 | 状态 |
|---|---|---|
| **Android（主）** | 8.0+（API 26+），arm64；**分发方式见 §12.7** | **做** |
| **Web（辅）** | Chrome / Edge / Safari 最近两个大版本；微信内置浏览器可**读**（答题） | **做** |
| **管理后台** | 桌面优先（≥1280 px），**不承诺移动端可用** | **做** |
| iOS | — | **不做**（2026-10-03 拍板；Flutter 保留扩展位，后续可低成本补） |
| 鸿蒙 HarmonyOS | — | **不做**（同上） |
| 微信小程序 | — | **不做**（Flutter 官方不支持编译到小程序，做则需单独原生实现） |

- 学生端**同一份 Flutter 代码**输出上述各端；仅按断点做布局分叉，**不维护两套业务逻辑**。
- **Android 分发（v2.3 定案）：官网直发 APK，不上任何应用商店。**
  - 官网提供**下载页**（版本号 / 发布日期 / 体积 / SHA-256 校验值 / 更新说明）；
  - **包名**：`cn.ccit.cwtc`（发布后**永不更改** —— 包名变了就是另一个 App）；
  - 详细流程与签名密钥管理见 **§12.7**。
  - **优点**：不依赖商店审核、不发软著/资质材料、迭代自由。
  - **代价（如实写明）**：Android 系统会提示"未知来源"，**首次安装体验略糙**；
    且**没有商店的分发与更新通道**，必须自己做**应用内更新提示**。

### 10.4 可维护性

- **内容与代码解耦**：课程 / 题目 / 证书元数据来自上游 JSON，**代码不写死任何课程名或题目**。
- **同步脚本可重跑**：`sync` 一条命令刷新全部内容，幂等。
- **一致性自检**：提供"内容体检"命令，检查资源齐备度、题库一致性、证书模板完整性、**知识库状态**。

### 11.3 关键设计：AI 网关（**为什么不让业务直连模型**）

业务代码**不直接调用大模型 SDK**，统一走自建 **AI 网关**，理由是**可替换、可控成本、可审计**：

```
学生提问 ──▶ AI 网关 ──┬─▶ ① 输入审核（内容安全）
                       ├─▶ ② 检索知识库（pgvector，限定 course_code）
                       ├─▶ ③ 组装 prompt（课程语料 + 检索片段 + 引用要求）
                       ├─▶ ④ 模型路由（分级：小模型兜底 / 大模型按需）
                       ├─▶ ⑤ 输出审核 + 引用校验（无引用则重试或降级回答）
                       └─▶ ⑥ 计量（token、耗时、额度扣减）+ 审计
```

- **引用校验是硬门禁**：模型返回若解析不出引用，**不返回给学生**，降级为"我去查资料"话术。
- **模型可换**：供应商变更只改网关配置，业务无感。
- **额度**：Redis 计数，按"学员 × 课程"，超限直接拒绝并提示。
- **凭据管理（v2.2）**：模型 API Key、支付商户密钥、短信密钥**全部经 `shared/.env` 注入**
  （`deploy/.env.example` 为模板），**不进代码库、不进日志**；
  凭据读写集中在网关内部，业务层**不接触**任何凭据原文（§12.2）。

### 11.4 未实测项（**如实标注，不给假设值**）

以下指标**本机没有实测条件**（无构建产物 / 无模型配额 / 无支付商户号），
**在拿到真实运行数据前不写数**，写进上线前必测清单：

| 项 | 为什么没测 | 何时能测 | 减重 / 优化方向 |
|---|---|---|---|
| Flutter Web 首屏 | 无 Web 构建产物 | M1 出可运行 Web 构建后 | 字体子集化、deferred loading、优先 WASM 渲染器 |
| AI 首字延迟 | 无模型服务配额 | M4 AI 网关接通后 | 流式输出、prompt 精简、检索 top-k 调参、区域就近接入 |
| 知识库重建耗时 | 未构建过索引 | M4 首次重建时 | 批量化 embedding、增量重建（按 checksum） |
| 支付回调端到端时延 | 无商户号 | M2 拿到商户号后 | 异步开通权益、回调先落库后再处理 |

### 11.5 与 CCIT 官网的接入方式（**技术实现，对应 §7.12**）

### 12.2 目录约定（沿用 cw-vopc）

```
/opt/cw-tc/
├── releases/
│   ├── 20261003-1030-abc123/     ← 每次发布一个时间戳目录
│   └── 20261003-1200-def456/

├── shared/

│   └── data/                      ← PostgreSQL 数据卷（跨版本保留）
└── backups/
```

**密钥与配置约定（v2.2，**按同系列其他项目一样处理**）**：

- 仓库内只保留 **`deploy/.env.example` 模板**（占位、无真实值，见 `.gitignore` 的 `!deploy/**/*.example`）；
- 服务器上复制为 **`/opt/cw-tc/shared/.env`** 并 **`chmod 600`**，
  由 systemd `EnvironmentFile=` 注入（与 ccit 的 `/etc/ccit/ccit.env` 同一套做法）；
- **涵盖四类凭据**：数据库口令 / Redis、**支付**（微信商户号与 API 密钥、支付宝应用私钥）、
  **大模型**（API Key）、**短信**（腾讯云密钥），以及 **身份证号加密密钥与 HMAC 密钥**；
- **任一类未配置即该功能 fail-closed 不启用**（沿用 ccit 的安全默认），
  但**加密密钥与 HMAC 密钥为强制项**，缺失则**服务拒绝启动**（不能明文暂存）。

**密钥的备份与轮换（v2.3 新增 —— 此前完全空白，属运营级单点）**：

| 密钥 | 能否轮换 | 丢失后果 | 要求 |
|---|---|---|---|
| `CWTC_ID_CARD_ENC_KEY`（AES-256-GCM） | **可轮换**（需保留旧密钥解历史数据） | **历史身份证号密文永不可解 → 无法补发证书** | **离线备份 ≥2 份异地**；轮换用 `key_id` 版本化，新旧并存 |
| `CWTC_ID_CARD_HMAC_KEY` | **不可轮换**（换了全部哈希失效） | **去重失效 + 无法按证件号定位学员** | **离线备份 ≥2 份异地**；**一旦启用视为永久** |
| `CWTC_SESSION_SECRET` | 可轮换（会导致全员重新登录） | 影响小 | 常规备份 |
| 支付 / 短信 / 模型密钥 | 可在渠道侧重置 | 功能中断，可恢复 | 渠道后台可查，常规备份 |

- **硬要求**：
  1. 加密密钥与 HMAC 密钥**必须有离线备份**（加密后存两处异地），
     **备份不得与数据库备份放同一介质 / 同一云账号**；
  2. **备份恢复演练必须包括"用备份密钥解密一条历史密文"** ——
     只验证"文件在"不算验证，**要验证它真的能解开**（§12.5 清单已列）；
  3. 密钥轮换流程写入 `docs/部署运维手册`（待建），轮换前必须先确认旧密钥仍在。
- **理由**：身份明文不落库是好事，但代价是**密钥成为唯一钥匙**。
  密钥丢了，数据库里那堆密文就是一堆废字节 —— 学员的证书**永远补不出来**，
  且**无法用技术手段挽回**。这条比备份数据库更要紧，因为数据库可从备份恢复，密钥不能。

### 12.6 staging / 沙箱环境（**v2.3 新增 —— 此前只有生产约定**）

**为什么需要**：支付、短信、AI 三件事**都无法在生产上试错** ——
发一条短信要花钱、调一次模型要花钱、付一笔款要真退款。
此前 PRD 只有生产环境约定，等于**逼着开发在线上联调**，必须补。

| 环境 | 域名 | 用途 | 关键差异 |
|---|---|---|---|
| **本地** | `127.0.0.1:8071` | 日常开发 | 支付/短信/AI **全部关闭**（fail-closed） |
| **staging** | `staging.cw-tc.ccit-agent.cn` | 联调与验收 | **微信支付沙箱 / 支付宝沙箱**；短信用**测试模板或直连日志不真发**；AI 用**小额度测试 key** |
| **生产** | `cw-tc.ccit-agent.cn` | 对外 | 真实资金与真实短信 |

- **硬要求**：
  1. **staging 的数据库与生产物理隔离**（不同实例 / 不同库，**绝不共用**）；
  2. staging **不得使用生产密钥**，也不得混用生产的支付商户号；
  3. **短信在 staging 默认不真发**（写日志 / 白名单号码），否则联调成本不可控；
  4. **AI 在 staging 用独立额度**，防止联调把生产额度刷空；
  5. 对外可访问性：staging **必须加访问限制**（Basic Auth 或 IP 白名单），
     否则会被搜索引擎抓到，出现"两套官网"。
- **验收**：staging 上跑通一次"注册 → 支付（沙箱）→ 学习 → 测评 → 发证"全链路。

### 12.7 Android 官网直发 APK（**v2.3 定案**）

**分发方式**：**官网直发 APK，不上应用商店**（刘老师 2026-10-03 拍板）。

#### 12.7.1 制品与下载页

- **包名**：`cn.ccit.cwtc` —— **一经发布永不更改**（改包名 = 新 App，老用户无法升级）。
- **产物**：`cw-tc-<versionName>+<versionCode>-<abi>.apk`（首发只出 **arm64-v8a**）。
- **官网下载页**展示：版本号、发布日期、**体积**、**SHA-256**、更新说明、最低系统要求（Android 8.0+）。
- **校验**：同时提供 `.sha256` 文件；页面显示哈希，便于用户自行核对。

#### 12.7.2 签名密钥（**最容易被忽略、代价最大的一环**）

| 项 | 要求 |
|---|---|
| 签名密钥库（`.jks`） | **离线保管，永不入库、永不进 CI 明文变量**；CI 用 GitHub Secrets 注入，构建后立即销毁临时文件 |
| **丢失后果** | **无法再发布可覆盖安装的升级包** —— 用户必须卸载重装、**学习与证书数据虽在服务端但本地态丢失**；**不可技术挽回** |
| 备份 | **≥2 份异地离线备份**（与 §12.2 的加密密钥同级对待） |
| 口令 | 与密钥库**分开保管**（不同人 / 不同位置） |

> ⚠️ 这条与 §12.2 的密钥备份是**同类问题**：**丢了都补不回来**。
> 区别是密钥丢了影响**发证**，签名丢了影响**发版**。

#### 12.7.3 应用内更新

- App 启动时请求 `GET /api/v1/app/latest?platform=android` 获取最新版本；
- 若 `versionCode` 高于本机 → **提示更新**（可选强制：低于最低支持版本时不可跳过）；
- **下载源走官网（或 COS + CDN）**，不走应用商店；
- **校验**：下载后**先校验 SHA-256 再安装**，防中间人替换。

#### 12.7.4 如实记录代价

| 好处 | 代价 |
|---|---|
| 不依赖商店审核，迭代自由 | 安卓会提示"未知来源"，**首次安装转化率会掉** |
| 不发软著 / 各类资质材料 | **没有商店的更新通道**，全靠自己做应用内更新 |
| 上架快 | **没有商店的安全扫描兜底**，包的安全性全靠自证（故必须给 SHA-256） |
| — | 学生若卸载 App，**只能回官网重新下载**（须在通知/邮件里保留下载入口） |
