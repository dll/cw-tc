## 1. 第三课堂是什么

### 1.1 三个课堂的由来

| | 第一课堂 | 第二课堂 | **第三课堂（本产品）** |
|---|---|---|---|
| 形态 | 线下、传统课堂 | 学校开设的第二课堂 | **在线、AI 驱动** |
| 组织者 | 任课教师 | 学校 / 团委 / 社团 | **平台 + AI + 教师** |
| 激励 | 学业成绩、学分 | 学分、综测 | **企业认证证书** |
| 时空 | 固定（课表） | 半固定（活动排期） | **完全自主（随时随刻）** |
| 进度 | 统一 | 统一 | **自适应、自定进度** |
| 内容来源 | 教师讲授 | 学校组织 | **AI 生成 + 教师审定 + 机器验真** |
| 评价 | 教师主观 + 期末考 | 参与记录 | **即测即评（机器判分 + 人工采点）** |
| 证书 | 无 | 无（记学分） | **畅网智能科技颁发，编号可验真** |
| **成本** | 学费 | 免费 | **按课程付费解锁（v2 新增）** |
| **陪学** | 教师答疑 | 无 | **AI 实时交互答疑（v2 新增）** |

**它不是"把线下课录成视频放到网上"**，而是四件事的重新组合：

1. **把"教"交给 AI 与课程资产**（教师从"讲授者"变成"审定者"）；
2. **把"学"交还学生**（自选课程、自定节奏、自定深度）；
3. **把"问"交给 AI**（随时可问、有据可查、越问越深）；
4. **把"证"接入产业**（不是学校发的学分，而是**企业发的、行业认的能力认证**）。

### 1.2 官方定义（用于对外）

> **第三课堂**是畅网智能科技推出的、以 AI 为引擎的自主学习教育平台。
> 它由 **AI 生成并维护课程内容**，学生以**手机号注册登录、身份证号实名**、**自主选择典型课程**、
> **付费解锁后在线学习并完成分级测评**，全程可**与 AI 实时交互答疑**并**导出学习笔记**；
> 通过后由 **畅网智能科技有限公司颁发能力认证证书**，证书编号公开可验真。

### 1.3 三个关键取向

**① 以典型课程为主，其它讲座为辅**

- **典型课程（主线）**：体系完整、有实验、有真机实测数据的课程。学生沿"讲 → 练 → 问 → 测 → 证"走完整条路。
  当前：**03-CF（C 语言，15 讲）· 05-OS（操作系统，22 讲）· 07-CN（计算机网络，17 讲）·
  06-CP（编译原理，16 讲）· 08-CC（计算机组成原理，16 讲）· 04-DB（数据库，10 讲）**。
- **讲座 / 专题（辅线）**：单点知识、案例复盘、行业视角。不单独发证，可作主线补充。
  当前：**02-DO（软件工程 · DevOps 案例课，10 单元）**。
- **一个学生可以只走一条主线拿一张证，也可以横向跨课凑齐多张证。**

**② 付费解锁，不做免费全开放（v2 新增）**

- 付费是**商业闭环**，也是**质量承诺**：收费意味着对内容与证书负责。
- 但**付费前必须能看清**：课程详情、讲次大纲、三档证书说明、价格全部公开可查；
  未付费可浏览与试学（试学讲次由管理员配置），**付费后才解锁学习与测评**。

**③ AI 是陪学，不是代考（v2 新增）**

- AI 的作用是**答疑、追问、补基础、联系统**，不是给答案。
- AI 回答**必须给出来源**（讲次 / 讲义文件 / 冻结输出），**说不上来就明说**。
- **测评期间 AI 关闭**（防作弊），交卷后可用 AI 复盘错题。

## 2. 第三课堂的十大特色

> 这十条是"为什么要有第三课堂"的答案，也是后面所有功能需求的**来源**。
> 每条给出：**是什么 → 凭什么成立 → 落到产品上是什么功能**。

### 特色一：**AI 是引擎，不是噱头**

- **是什么**：课程内容、练习题、解析、判分规则由 AI 大规模生成，**但关键判据由人拍板**；
  v2 起，AI 进一步成为**学生的实时陪学**（§7.5）。
- **凭什么成立**：上游 8 门课程已跑通"**AI 起草 → 人定判据 → 机器验真**"的流水线，
  累计产出 **19 份 AI 草稿 / 3827 行**，其中**主动留空 27 个常数等人工填写**。
- **产品功能**：内容后台的"AI 草稿区"（原始稿与人工稿并存可对照）、每条内容的"来源标注"、
  **学生端 AI 助教（回答必附出处）**。

### 特色二：**数字必须真、口径必须写明**

- **是什么**：平台展示的每个数字都必须能追到出处；范围优于单点；测不出的**标【未取到】**。
- **凭什么成立**：上游课程有四类数字标注（【实测】【真机读数】【协议常数】【他方实现】），
  且有 `_range.py` 报范围、`_verify.py` 判据、冻结输出文件可逐字核对；题库 **1204 道题**的参考答案均可溯源。
- **产品功能**：内容区强制"证据链"字段（数字 → 出处 → 类别）；测评解析保留"口径说明"；
  **AI 助教的每条回答都带引用**，无据不答。

### 特色三：**即测即评，客观题机器判**

- **是什么**：学完就测，单选/判断/填空**当场出分**；主观题给"待人工阅卷"清单。
- **凭什么成立**：7 门课都配了 **`_grade.py` 自动判分程序**，**523 道客观题**可自动判分，
  且**每门都能自检满分**（02-DO 114 · 03-CF 130 · 04-DB 47 · 05-OS 54 · 06-CP 56 · 07-CN 63 · 08-CC 59）。
- **产品功能**：在线答题 → 客观题实时判分 → 主观题进入采点队列；**填空标为"半自动"**（宽松匹配，必须抽查）。

### 特色四：**分级测评，能力可分层**

- **是什么**：每门课三档 —— **L1 通识 / L2 工程师 / L3 架构师**，对应三张不同的证书。
- **凭什么成立**：题库已按 L1/L2/L3 组织，**合格线统一**
  （L1 60/75/90 · L2 70/82/92 · L3 80/90/96），且每档题型不同。
- **产品功能**：学生可**逐级考**（推荐）或**跳级考**（需满足前置）；成绩单按档记档。

### 特色五：**企业颁发、编号可验真的证书**

- **是什么**：通过测评 → 生成正式证书（PDF）→ 编号可公开查真。
- **凭什么成立**：编号规则 `CW-{课程码}-{级别位}{年份}{流水号6位}`（例 `CW-CN-M202600137`），
  7 门课各有**三档空白模板 + 合订预览 + 虚构样例**，且**布局校验全过**。
- **产品功能**：自动判证 → 生成 PDF → 分配编号 → 写入"证书台账" → **公开验真页**。

### 特色六：**实名制，身份与证书绑定**

- **是什么**：学生用**手机号注册登录**、以**身份证号完成实名**，证书与真实身份绑定，
  **一生一号一证**（同课同级不重复颁发）。
- **凭什么成立**：证书上本就印有身份证号；上游 `保密说明.md` 已明确**默认脱敏**（前 6 + 8★ + 后 4）。
- **产品功能**：注册即实名核验（格式 + 校验位），**手机号与身份证号各司其职**（§7.1 A-0）；
  证书默认脱敏打印；**详见 §9**（身份证号不落明文，验证码接口防刷见 §9.6）。

### 特色七：**多课程矩阵，按专业找课**（v2 强化）

- **是什么**：7 门课形成矩阵 —— **竖着走**是一门课由浅到深（L1→L3），**横着走**是多门课各拿一张证；
  v2 起课程**按专业分类**，学生按自己的专业找课。
- **凭什么成立**：课程资产已统一（见 §6），题库 schema、证书命名、合格线全部一致。
- **产品功能**：课程广场（**按专业 / 主线辅线筛选**）、个人"能力地图"。

### 特色八：**自主学习，路径自己拼**

- **是什么**：没有课表、没有排期。学生自定"学哪门、学到哪一级、什么时候考"。
- **凭什么成立**：每讲资源自足（课件 / 讲义 / 口播稿 / 配音 / 实验 / 冻结输出 / 思考题），
  且平台提供**可选的推荐路径**（不是强制进度条）。
- **产品功能**：学习路径推荐、断点续学、错题本、**可选**的每日目标。

### 特色九：**资源即资产，全部可核对**

- **是什么**：每个数字、每段结论都能对到一份**冻结输出文件**（真机跑出来的）。
- **凭什么成立**：以 07-CN 为例，讲级资源含 **25 份课件 / 118 份 Markdown / 133 个代码文件 /
  45 份冻结输出 / 374 条配音**；全平台合计 **1204 题 / 7916 分**。
- **产品功能**：内容详情页可"查看原始输出"；
  v2 起这些资产**同时是 AI 知识库的语料**（§7.5.2）——问得到、也查得到。

### 特色十：**可交接、可复现、可持续**

- **是什么**：AI 生成的内容不是黑箱 —— 换个人接手，能跑、能改、能重制。
- **凭什么成立**：上游全部课程都有"**生产管线交接手册**"、`_ai_draft/` 原始稿一字未改、
  每讲有使用说明 / 思考题 / 接续说明，且**资源体检工具**（`_audit_resources.py`）证明 7 门课资源全部备齐。
- **产品功能**：后台"内容体检"面板（资源齐备度、题库一致性、证书模板完整性、**知识库构建状态**一键自检）。

### 3.3 典型画像

**画像 A：大三学生 · 小林（主线学习者）**
- 想补"计算机网络"，线下进度固定、听不懂没法倒回去。

## 7. 功能需求（模块级）

> 标记：`[P0]` 首发必须 · `[P1]` 首发后补 · `[P2]` 远期。每条给出**可测的验收标准**。

### 7.1 账号与实名（模块 A）—— **v2 重构 / v2.1 调整账号口径**

#### A-0 `[P0]` 账号口径（**v2.1 定案，一句话说清**）

| 用途 | 用什么 | 约束 |
|---|---|---|
| **登录账号（主）** | **手机号** | 全局唯一；换绑需双向验证（A-3） |
| **实名与证书绑定** | **身份证号** | 全局唯一（哈希去重）；**终生不改**；不用于登录 |
| 通知 / 找回 / 客服定位 | **手机号** | 同登录账号 |
| ~~学号~~ | **不采用** | 跨校不通用、可能变更、非本人可控标识（A-5） |

> **为什么要两个都用**：手机号**适合作账号**（微信 / 支付宝生态绑定紧、可收发验证码、可换绑），
> 身份证号**适合做实名与证书**（一生一号一证、证书上要印）。
> **两个都采集，各司其职**，而不是让身份证号去兼任登录账号。

#### A-1 `[P0]` 实名注册

- **输入**：真实姓名 + **手机号** + 短信验证码 + 密码 + **身份证号**。
- **处理**：
  1. **手机号**：格式校验 + 短信验证码（即完成"号码可用"验证）→ **作为登录账号**，**唯一约束**；
  2. **身份证号**：**格式 + 校验位校验**（GB 11643-1999 加权校验，本地可算，不依赖第三方）；
     入库前算 `id_card_hash = HMAC-SHA256(身份证号, 服务端密钥)` 作**唯一索引**，
     并以 **AES-256-GCM 密文**留存（仅供制证时解密，见 §9.2）；
     **明文一律不落库、不进日志**；
  3. **姓名**：格式校验；
  4. 密码强度校验（8–20 位，含字母 + 数字；弱口令库拦截；**不得使用身份证后 6 位或生日**）；
  5. 生成**学员号**（如 `TC2026-000137`，**平台内部编号**，不可改，**不是账号**）；
  6. 记录**同意条款**（用户协议 / 隐私政策 / **付费与退款政策**）的时间戳与版本号。
- **验收**：非法身份证（校验位错）被拒；**同一手机号不允许重复注册**；
  **同一身份证号也不允许重复注册**（防一人多号）；注册成功后可立即登录；
  **任何接口与日志都不得返回明文身份证号**。

#### A-2 `[P0]` 登录（**手机号为主**）

- **方式**：
  - **手机号 + 短信验证码**（默认，最常用，与支付/找回同一套号码）；
  - **手机号 + 密码**（可选，适合常用设备）。
- **防护**：
  - 登录页**强制图形 / 滑块验证码**；
  - 连续失败 5 次锁定 10 分钟（**按账号 + 按 IP 双维度**）；
  - **登录请求走 HTTPS POST body**，手机号与身份证号都**不进 URL / query / Referer**；
  - 异地 / 新设备登录触发**短信 + 站内告警**。
- **验收**：错码锁定生效；登录态有效期 ≤ 7 天；支持"登出全部设备"；
  **日志全文检索无明文身份证号**（由 `deploy/scripts/scan-sensitive.sh` 门禁）。

#### A-3 `[P0]` 找回、改密与换绑手机号

- **找回密码**：手机号短信验证 → 重置密码。
  **不暴露"该手机号是否已注册"**（统一话术"若该号码已注册，短信已发送"），防账号枚举。
- **换绑手机号**：**旧号验证 + 新号验证**双重确认 → 换绑；换绑后旧号立即失效。
  **换绑不影响**：证书、订单、学习权益、笔记（这些都挂在**身份证号 / 学员号**上，不挂在手机号上）。
- **可改**：密码、手机号（走换绑）。**不可改**：姓名、身份证号 —— 需走**人工申诉**（防冒用）。

#### A-4 `[P1]` 注销与数据删除

- 证书依法留存（编号台账），**身份信息可匿名化**，需人工审核（沿用 v1 §9.4）。

#### A-5 `[P0]` **不采用学号**（v2.1 明确排除）

- **学号不作为**：登录账号、唯一标识、证书编号组成部分。
- **理由**：跨校不通用；在校期间可能变更；学号由学校分配、**非本人可控**，
  不适合作为"一生一号一证"的锚点。
- **替代**：对外标识用手机号（登录）+ 学员号（平台内部）；实名锚点用身份证号。
- **验收**：数据库中**不存在**以学号为主键 / 唯一键的表或字段。

### 7.2 课程与专业分类（模块 B）

#### B-1 `[P0]` 课程广场

- **展示**：课程卡片（名称 / **专业** / 类型 / 讲数 / 题量 / **价格** / 三档证书名 / 是否主线）。
- **筛选**：**按专业** / 主线辅线 / 全部；支持按名称搜索；按就绪度与排序权重排列。
- **数据源**：课程内容来自 `课程总览.json`（**只读同步，不写死**）；
  **专业、价格、上架状态来自平台自身元数据**（`course` 扩展字段，§8.4）。
- **验收**：课程列表与上游一致；新增课程只需更新上游 JSON + 资源 + **管理员设专业与价格**，**不改前端代码**。

#### B-2 `[P0]` 课程详情与讲次导航

- **展示**：课程简介、**所属专业**、**价格与购买按钮**、三档证书说明、讲次列表（可展开）。
- **每讲**：标题、资源清单（课件 / 讲义 / 视频 / 音频 / 实验 / 冻结输出 / 思考题）。
- **试学**：管理员可为课程配置**免费试学讲次**（默认 0 讲），未付费可看。
- **验收**：**未拥有的资源（如某课无视频）不显示空位**；
  未付费时讲次内容区显示"**付费后解锁**"而非空白。

#### B-3 `[P0]` 专业分类（**平台自管，见 §6.4**）

- **专业字典**：管理员可新增 / 改名 / 停用专业；停用**不影响**已挂课程。
- **课程挂专业**：一门课挂**一个**专业（单选）。
- **建议初始专业**（**平台建议、待管理员确认，非上游数据**）：
  计算机科学与技术 / 软件工程 / 网络工程 / 数据科学与大数据技术。
- **验收**：课程广场按专业筛选结果与后台配置一致；专业改名后**前台同步更新**。

#### B-4 `[P0]` 资源查看器

- **HTML 课件**：**App 端必须走 WebView**（`flutter_inappwebview`），Web 端走 iframe。
  原生渲染无法还原课件的动画与节拍，**这是硬约束**。
- **Markdown**：渲染为网页（代码高亮、表格）。
- **音频/视频**：App 端原生播放器（倍速、断点、后台播放）；Web 端浏览器播放器。
- **冻结输出**：等宽渲染，**保留原始换行**（数字可对账）。
- **验收**：大文件（>10 MB 的 HTML）不卡死；播放位置可记忆；
  **跨端口径 —— 正文与数字必须一致，表现允许有差异**。

#### B-5 `[P0]` 我的课程 / 断点续学

### 7.3 支付与订单（模块 G）—— **v2 全新增**

> **原则**：**付费前看得清，付费后学得稳，退款有章可循。**

#### G-1 `[P0]` 课程定价

- **定价主体**：**管理员**（§7.10.2）。
- **模型（v2 取值）**：**按课程整门定价** —— 一个价格解锁该课程的**全部讲次与 L1/L2/L3 三级学习与测评**。
  按等级分别定价列为**可选扩展**（§16-13）。
- **单位与展示**：人民币**元**；支持"原价 / 现价"（活动用，可选）。
- **免费课程**：价格设为 0 即免费，下单流程跳过支付直接开通。
- **验收**：改价**只影响新订单**，不影响已支付订单与既有权益。

#### G-2 `[P0]` 下单与扫码支付

- **流程**：课程详情 → 点"购买" → 创建订单（**快照课程名与当时价格**）→
  展示**支付二维码** → 用户扫码 → 支付结果确认 → **开通权益** → 站内通知。
- **支付方式（v2 取值）**：
  - **Web 端**：**微信支付 Native（扫码）** + **支付宝当面付（扫码）**；
  - **App 端**：调起 **微信支付 / 支付宝** SDK。
  - 最终渠道组合见 §16-12（建议两个都上，互为兜底）。
- **结果确认双通道**：**支付渠道异步回调（主）** + **前端轮询订单状态（辅）**；
  两者都必须**幂等**（同一订单重复回调只生效一次）。
- **验收**：支付成功后 ≤ 3 s 内权益生效；订单与回调均有完整日志；
  回调**验签失败一律拒绝并告警**。

#### G-3 `[P0]` 订单与对账

- **订单状态**：待支付 / 已支付 / 已关闭 / 已退款。
- **对账**：每日与支付渠道对账（笔数、金额），**差异必须为 0**，异常触发告警。
- **验收**：订单可导出 CSV；可按学员 / 课程 / 时间 / 状态检索。

#### G-4 `[P0]` 退款 → **连带撤销证书**（v2.2 决策）

- **发起**：管理员在订单页发起**全额退款**（部分退款为 P1）。
- **联动（三件事同一流程完成）**：
  1. **撤销该订单对应的学习权益** —— 学员回到该课程的"未解锁"状态；
  2. **撤销该课程已签发的证书**（若已签发）—— 证书状态置为「**已撤销**」，
     撤销原因记为「**订单已退款**」，写入证书台账；**原编号不可重新分配**；
  3. **保留**订单、支付流水、退款记录与证书台账条目 —— **只标记状态，不删除**。
- **理由（刘老师 2026-10-03 拍板）**：**"退款就把证书取消掉，这个才合理。"**
  退款意味着这门课**并未真正获得**，证书因此失去成立的**前提**。
  这与"证书证明能力"不矛盾 —— 证书证明的前提，是**通过正规付费路径取得的学习资格**。
- **退款后重新购买**：该学员可**再次购买**同一课程；
  若再次通过测评，**重新发证（分配新编号）**；
  旧编号**永久保持「已撤销」**（不复活、不复用）。
- **验收**：退款后 ① 课程回到"未解锁"；
  ② **验真页查原编号显示「已撤销」**；
  ③ 退款与撤销记录均可追溯；
  ④ 渠道退款失败**有重试与告警**；
  ⑤ **不得出现"退了款、证书仍有效"的中间态** —— 两步须在同一业务操作内完成，
  失败则整体回滚并告警。

- 开票需求见 §16-16。

### 7.5 AI 助教与课程知识库（模块 H）—— **v2 全新增**

> **一句话**：**AI 只答这门课，而且必须说明依据。**

#### H-1 `[P0]` AI 实时交互答疑

- **入口**：学习页随时唤起；可"针对当前讲次提问"或"针对当前题目提问"。
- **形态**：对话式，**流式输出**。
- **回答原则（硬约束）**：
  1. **只基于本课程知识库**（§7.5.2）作答，**每条回答必须附来源**
     （讲次 / 讲义文件 / 冻结输出），来源可点开跳转到对应资源；
  2. **无依据就明说**"这门课的资料里没有这条"，**不编**；
  3. **越界拒答**：与课程无关的问题礼貌拒答并引导回课程；
  4. **不给测评答案**：测评进行中 AI 关闭；交卷后可讲解思路，**不给标准答案原文**。
- **上下文**：自动带入"当前课程 + 当前讲次"，支持追问。
- **额度与成本**：按"学员 × 课程"设**每日 / 总提问额度**（管理员可调，§7.10.2）；
  常见问题缓存；模型分级路由（§11.4）。
- **验收**：**带引用比例 100%**（硬门禁）；测评期间 AI 入口强制关闭；额度用尽有明确提示。

#### H-2 `[P0]` 课程知识库生成

- **语料**：上游课程资产的 **Markdown 讲义 / 课件正文 / 冻结输出 / 实验说明**（**只读同步，不改上游**）。
- **构建流程**：同步 → 切片（按讲次 + 标题层级）→ 向量化（Embedding）→ 入向量库 → 建索引。
- **构建主体**：管理员在后台**一键重建**（按课程 / 全量）；与内容 `sync` 联动。
- **可核对**：后台显示**切片数 / 向量数 / 最后构建时间 / 构建耗时**（**数字要有出处**，不写死）。
- **验收**：**不包含**已签发证书、`_ai_draft/` 原始稿等非公开内容；
  重建可重入（重复构建结果一致）；知识库缺失时 AI **明确降级提示**而非胡说。

#### H-3 `[P1]` 知识点检索与关联

- 学生可搜知识点 → 返回对应讲次与讲义片段（复用知识库索引）。

#### H-4 `[P1]` 学情智能摘要

- 教师可看某课的**共性问题聚类**（基于 AI 提问与错题），辅助改进内容。

### 7.7 测评与判分（模块 C）

#### C-1 `[P0]` 在线答题

- **前置**：**课程已解锁**（付费或免费）才可参加测评。
- **题型**：单选、判断、填空、名词解释、简答、计算、代码阅读、编程、实验设计、对比分析、系统设计、故障归因、选型评审、综合论证。
- **组卷**：从 `题库.json` 按等级抽题。
- **交卷**：客观题即时判分；主观题入"待阅卷"队列。
- **防作弊**：**测评期间 AI 助教关闭**；切屏 / 离开行为记录（提示，不强制中断）。
- **验收**：断网重连不丢答案；交卷后不可再改（成绩单可查）。

#### C-2 `[P0]` 组卷策略（按等级）

| 等级 | 卷面组成（参考上游 README） | 满分 |
|---|---|---|
| L1 | 单选 20 + 判断 10 + 填空 6 + 名解 3 + 简答 6 | 100 |
| L2 | 计算 4 + 工件阅读 2 + 实验设计 2 + 对比分析 2 | 100 |
| L3 | 系统设计 1 + 选型评审 1 + 综合论证 1 + 故障归因 1（+ 跨章综合） | 100 |

- **可组卷套数**：由题库实时计算（**按题型逐项算、取最紧的一项**）；不足时**界面明示"本档当前可组 N 套"**。
- **验收**：同一学生重考时**优先避开已做过的题**（题量允许时）。

#### C-3 `[P0]` 客观题自动判分

- **复用上游 `_grade.py` 判分规则**：单选严格匹配（容忍大小写/全角）；
  判断接受 `√ × T F true false 1 0`；填空**宽松匹配 + 按空给分**。
- **硬门禁**：上线前必须**移植并跑通 `--self-test`**（标准答案必须满分）。
- **验收**：**填空界面明确标注"半自动，需抽查"**；判分日志可追溯。

#### C-4 `[P0]` 主观题阅卷（采点制）

- **流程**：待阅列表 → 按"评分要点"逐条采点 → 系统累加 → 分档。
- **执行者**：**教师**（v2 角色归并，见 §3.1）。
- **功能**：双人阅卷（差值超阈值触发第三人）、给分备注、批量操作。
- **验收**：采点项与题目的评分要点**逐条对应**。

#### C-5 `[P0]` 成绩与分档

- **分档**：L1 60/75/90 · L2 70/82/92 · L3 80/90/96；L2/L3 叠加单科最低分。
- **成绩单**：总分、各题型得分、分档、是否达标、**口径说明**。
- **验收**：分档计算与 `课程总览.json` 的 `bands` **完全一致**。

#### C-6 `[P1]` 重考与补考

- 未达标可重考（次数可配）；记录**每次成绩**（不覆盖历史）。

#### D-5 `[P1]` 证书下载与分享

- **平台自有数据不参与同步**：`major`、`price_*`、`status`、`entitlement`、`order` 等
  **全部是本平台数据**，上游怎么改都不动它们（这是 §6.4 的落地约束）。

## 9. 安全与合规（**本产品的红线**）

> 本产品采集**身份证号**，属《个人信息保护法》定义的**敏感个人信息**；
> 同时涉及**在线支付**与**生成式 AI**。这一节是**上线的前提**：
> 任一条不满足，都不得对真实学生开放。
>
> **v2.1 口径**：**登录账号是手机号，身份证号只做实名与证书绑定** ——
> 这**降低**了攻击面（手机号不像身份证号那样可被构造枚举），
> 但**新增**了短信验证码接口的防护要求（§9.6）。

### 9.1 数据最小化

| 数据 | 是否采集 | 用途 | 留存 |
|---|---|---|---|
| 姓名 | 是 | 证书署名 | 长期（与证书绑定） |
| **手机号** | **是（必须）** | **登录账号** + 验证码 + 找回 + 通知 + 支付客服定位 | 长期 |
| **身份证号** | **是（必须）** | **实名 + 证书编号绑定**（**不用于登录**） | 长期（**加密 + 哈希，永不存明文**） |
| 出生日期/性别 | **否** | — | **不从身份证号推导存储** |
| 住址 | **否** | — | — |
| **学号** | **否** | — | **明确不采集、不做标识**（§7.1 A-5） |
| **支付信息** | **否（本平台不存卡号）** | 支付由微信 / 支付宝托管 | **不落地任何支付凭据** |

**原则**：能证明"是谁"就够了，不采集、不推算、不存储任何多余信息。

### 9.2 存储要求（硬性）

1. **明文绝不落库**：身份证号入库前以 **AES-256-GCM** 加密（密钥由环境变量 / KMS 注入，**不进代码库**）。
2. **两个唯一约束**：
   - `phone` —— **登录账号**，唯一索引（可换绑，换绑即改此值）；
   - `id_card_hash = HMAC-SHA256(身份证号, 服务端密钥)` —— **实名去重**，唯一索引，
     **不用于登录**；不可逆，泄露也无法还原。
3. **展示一律脱敏**：身份证号默认 `前6位 + ******** + 后4位`（`110101********1234`）；
   手机号默认 `138****5678`。
4. **日志脱敏**：所有日志、错误上报、监控埋点**必须过滤身份证号与手机号**（正则过滤器 + 单测）。
5. **支付凭据**：本平台**不存储**银行卡号、CVC、支付密码；只保存渠道返回的**交易号**。

### 9.3 传输与访问

- **全站 HTTPS**（腾讯云免费证书 + nginx，强制 HSTS）。
- 数据库、缓存**不对公网开放**（安全组只放 80/443/22）。
- 后台接口走**独立鉴权**（管理员 Token + 二次验证），操作全部进 `audit_log`。
- **验真页防刷**：按 IP 限频（如 20 次/分钟），**不回显完整身份证号**。

### 9.4 用户权利（必须实现）

| 权利 | 实现 |
|---|---|
| 知情同意 | 注册时明示"采集什么、做什么用、存多久"，**勾选同意**（版本化留痕） |
| 查询 | 个人中心可看自己的实名信息（脱敏）与全部证书 |
| 更正 | 手机号可自助改；姓名 / 身份证走人工申诉 |
| 删除 | **注销账号**：证书依法留存（编号台账），**身份信息可匿名化**，需人工审核 |
| 撤回同意 | 支持，撤回后停止使用相应信息（已发证书仍可按编号验真） |
| **AI 会话** | 学员可**自行删除** AI 会话与笔记；删除后不再作为任何用途 |

### 9.5 证书颁发的合规边界

- 证书**必须**标明：颁发主体、课程、等级、成绩、编号、签发日期。
- **不得**暗示"国家认证""官方资格"；证书是**企业能力认证**，非学历、非职业资格。
- 已签发证书进**独立台账**；模板与已签发件**不放入公开代码库**。

### 9.6 ⚠️ **账号与验证码的风险与对策（v2.1 改写）**

**口径变化**：v2.0 曾用**身份证号**作账号，风险是"**身份证号可被构造枚举**"；
v2.1 改回**手机号**作账号，该风险**消失**（手机号不可构造）。
但换来**新的风险面 —— 短信验证码接口**（可被刷、直接产生费用）。**两者都要防**。

| # | 风险 | 对策（**全部强制**） |
|---|---|---|
| 1 | **短信轰炸 / 接口刷量**（**v2.1 新增首要风险**，直接烧钱） | ① 发码前**必须先过图形/滑块验证码**；② **单手机号日上限**（如 10 条/日）；③ **单手机号 60 s 冷却**；④ **单 IP 限频**；⑤ 同号短信内容与间隔做**去重**；⑥ 短信费用**日额度告警** |
| 2 | **手机号撞库**（外部泄露的手机号库） | 登录**强制图形验证码**；失败 5 次锁定（账号 + IP 双维度）；登录接口独立限频 |
| 3 | **弱口令** | 8–20 位含字母 + 数字；**弱口令库拦截**；**禁止身份证后 6 位 / 生日作密码** |
| 4 | **敏感信息泄露于 URL / 日志** | 登录与注册走 **POST body**；手机号、身份证号**禁止**出现在 query、Referer、埋点、错误堆栈；日志正则过滤 + **单测守门** |
| 5 | **凭证被盗后横向** | 敏感操作（**换绑手机号** / 改密 / 注销 / 退款申请）需**短信二次验证** |
| 6 | **一人多号** | `phone` 唯一 + `id_card_hash` 唯一，**双层去重**；注册接口幂等 |
| 7 | **找回接口泄露注册状态** | 统一话术，**不区分**"已注册 / 未注册" |
| 8 | **换绑被劫持** | 换绑需**旧号 + 新号双向验证**；换绑后**通知原手机号**；7 天内**不得二次换绑** |
| 9 | **前端缓存残留** | 登录表单关闭自动填充历史；**不写入 localStorage** |

- **上线门禁**：
  - `deploy/scripts/scan-sensitive.sh` 必须报 **0 命中**（代码 + 日志 + 响应体 + 测试快照）；
  - **渗透自测（登录）**：脚本对登录接口做 100 次无效尝试，验证锁定与限频生效；
  - **渗透自测（短信）**：脚本对发码接口做**超频尝试**，验证图形验证码前置、日上限、冷却均生效。
- **关于支付与手机号的关系（**避免一个常见误解**）**：
  手机号作账号**便于**找回、通知与客服定位；但**微信 / 支付宝的支付回调不携带用户手机号**，
  因此**对账与订单关联一律以「订单号 + 渠道交易号」为准**，
  **不得**用手机号作为支付对账键。

### 9.7 支付合规（v2 新增）

- **资质前提**：微信支付 / 支付宝商户号需**企业资质**（畅网智能科技营业执照、对公账户）；
  **资质未办下来前，支付功能不得上线**（可用"免费课程"模式先跑内容闭环）。
- **必备文本**：**用户协议**、**隐私政策**、**付费与退款政策**
  （含退款条件、时限、流程，**并明示"退款后已发证书将被撤销"**），
  注册时勾选、页脚可随时访问。
- **不夸大**：课程页不得出现"包过""保过""包就业"等承诺性表述。
- **资金安全**：回调**验签**、金额**二次核对**（订单金额 vs 渠道金额）、**对账差异为 0**。
- **审计**：退款、改价、下架等**资金与商业动作全部留痕**（谁、何时、原值 → 新值）。

### 9.8 AI 合规（v2 新增）

| 要求 | 落地 |
|---|---|
| **生成内容标识** | AI 回答区域**显著标注"内容由 AI 生成，仅供参考"**（法规要求） |
| **内容安全** | **输入 + 输出双向审核**（敏感词 / 违规内容过滤），命中即拦截并记日志 |
| **语料合法** | 知识库语料**仅来自自有课程资产**（上游 8 门课，团队自行生产），**不抓取第三方内容** |
| **数据不出境** | 优先选用**国内合规模型服务**；若用境外模型，则**不发送个人信息**（仅课程语料），并评估合规 |
| **可追溯** | 每次调用记录模型、token 数、耗时；**不记录**身份证号 |
| **投诉举报** | 提供对 AI 回答的"举报 / 纠错"入口，管理员可下架问答 |
| **不替代人工** | 证书发放**不依赖 AI 判断**（判分与分档是确定性规则，AI 不参与） |

### 9.9 未成年人

- 本平台面向**高校学生**（一般已成年）。若实际存在未成年学员，
  **需监护人同意**并限制 AI 会话留存 —— **该项待确认，见 §16-18**（如实标注，不假定）。

### 11.3 关键设计：AI 网关（**为什么不让业务直连模型**）

业务代码**不直接调用大模型 SDK**，统一走自建 **AI 网关**，理由是**可替换、可控成本、可审计**：

```
学生提问 ──▶ AI 网关 ──┬─▶ ① 输入审核（内容安全）
                       ├─▶ ② 检索知识库（pgvector，限定 course_code）
                       ├─▶ ③ 组装 prompt（课程语料 + 检索片段 + 引用要求）
                       ├─▶ ④ 模型路由（分级：小模型兜底 / 大模型按需）
                       ├─▶ ⑤ 输出审核 + 引用校验（无引用则重试或降级回答）
                       └─▶ ⑥ 计量（token、耗时、额度扣减）+ 审计
```

- **引用校验是硬门禁**：模型返回若解析不出引用，**不返回给学生**，降级为"我去查资料"话术。
- **模型可换**：供应商变更只改网关配置，业务无感。
- **额度**：Redis 计数，按"学员 × 课程"，超限直接拒绝并提示。
- **凭据管理（v2.2）**：模型 API Key、支付商户密钥、短信密钥**全部经 `shared/.env` 注入**
  （`deploy/.env.example` 为模板），**不进代码库、不进日志**；
  凭据读写集中在网关内部，业务层**不接触**任何凭据原文（§12.2）。

### 11.4 未实测项（**如实标注，不给假设值**）

以下指标**本机没有实测条件**（无构建产物 / 无模型配额 / 无支付商户号），
**在拿到真实运行数据前不写数**，写进上线前必测清单：

| 项 | 为什么没测 | 何时能测 | 减重 / 优化方向 |
|---|---|---|---|
| Flutter Web 首屏 | 无 Web 构建产物 | M1 出可运行 Web 构建后 | 字体子集化、deferred loading、优先 WASM 渲染器 |
| AI 首字延迟 | 无模型服务配额 | M4 AI 网关接通后 | 流式输出、prompt 精简、检索 top-k 调参、区域就近接入 |
| 知识库重建耗时 | 未构建过索引 | M4 首次重建时 | 批量化 embedding、增量重建（按 checksum） |
| 支付回调端到端时延 | 无商户号 | M2 拿到商户号后 | 异步开通权益、回调先落库后再处理 |

### 11.5 与 CCIT 官网的接入方式（**技术实现，对应 §7.12**）

- **方向一（官网 → 本产品）**：官网 `products[]` 增加 `cw-tc` 项，`path` 指向本产品入口。
  **改动在 CCIT 仓库**，本产品只需提供稳定的入口地址（`https://cw-tc.ccit-agent.cn`）。
- **方向二（官网 ← 本产品）**：本产品提供 `GET /api/v1/public/status`（**只读、聚合、脱敏**，§7.12 K-2），
  由官网后端拉取或由本产品前端直出快照。**不可用时如实返回 `unavailable`**。
- **域名**：`cw-tc.ccit-agent.cn` 已在公司域 `ccit-agent.cn` 下，**无需额外备案主体**（沿用公司主体）。
- **不做的**：本产品**不自建**第二套公司级身份系统；不与 AOC 混用学员身份（§7.12 K-4）。

**密钥与配置约定（v2.2，**按同系列其他项目一样处理**）**：

- **任一类未配置即该功能 fail-closed 不启用**（沿用 ccit 的安全默认），

## 15. 验收标准（**v2.2 可发布 = 以下全过**）

### 15.1 功能验收（端到端）

- [ ] 学生用**手机号**注册成功，**重复手机号被拒**；身份证号校验位错误被拒
- [ ] **同一身份证号**二次注册被拒（一人一号）
- [ ] 学生用**手机号 + 验证码**（及**手机号 + 密码**）均可登录；**连续错码 5 次锁定**
- [ ] **换绑手机号**：旧号 + 新号双向验证通过；换绑后**证书与订单不受影响**
- [ ] **短信防刷**：图形验证码前置、单号日上限、60 s 冷却、单 IP 限频**均生效**
- [ ] 学生能**按专业筛选**课程，列表与后台配置一致
- [ ] 未付费可看**课程详情与试学讲次**；讲次内容区显示"付费后解锁"
- [ ] **扫码支付**成功 → ≤ 3 s 内课程解锁
- [ ] **重复回调**不重复开通权益（幂等）
- [ ] 管理员**退款**成功 → 权益撤销、**已签发证书同步撤销**、订单与台账留痕
- [ ] 退款后验真页查原编号 → 显示「**已撤销**」
- [ ] 退款后**重新购买并通过测评** → **重新发证（新编号）**，旧编号仍为「已撤销」
- [ ] **不存在**"退了款而证书仍有效"的中间态

- [ ] AI **答不上来时明说**，不编造
- [ ] 测评期间 **AI 入口关闭**
- [ ] 学生能把 AI 回答/手写内容**存为笔记并导出 Markdown**
