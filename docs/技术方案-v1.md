## 1. 后端目录与分层

### 1.1 一条纪律：**按业务模块切包，不按技术分层切包**

```
packages/server/
├── cmd/
│   ├── server/            ← 唯一入口（配置校验失败即拒绝启动）
│   └── {sync,aicheck,kbcheck,rolecheck,coursecheck,insightcheck,cfgcheck,publiccheck}/
│                          ← **门禁与运维子命令**（AGENTS 质量门禁直接调它们）
├── internal/
│   ├── platform/          ← 跨模块能力：db · redis · log · redact · audit · clock · idgen · cos · httpclient
│   ├── <模块包>/           ← 每个业务模块一个包，**handler/service/repo 同包内分层**
│   └── ...
├── migrations/            ← 迁移 0001~0019（**数据字典 §8 是唯一定义**）
└── Makefile
```

**为什么不按 `controller/ service/ dao/` 切**：本产品有 17 个模块、39 张表级小节。
按技术切的结果是**一个模块的代码散在 5 个目录里**，改一个需求要开 5 个文件；
按模块切则**一个模块一个包**，边界与 PRD 的模块编号一一对应，找代码等于查表。

## 2. 十条关键设计决策（**每条都给"为什么"**）

### 2.1 事务边界：**一次业务操作 = 一个事务**

| 操作 | 同一事务内必须一起完成的事 |
|---|---|
| **支付回调** | 写 `payment_txn` + 订单置 `paid` + **开通 `entitlement`** + 写审计 |
| **退款** | 撤 `entitlement` + **撤销证书**（原因「订单已退款」）+ 写 `refund` + 写审计 |
| **发证** | 原子取号（`cert_no_sequence`）+ 写 `certificate` + 写审计 |
| **课程下架** | 课程置 `unpublished` + **运营位置 `removed`** + 撤宣传位 |
| **离线授权撤销** | 退款时置 `download_grant.status='revoked'` |
| **优惠码核销** | 写 `promo_redemption` + 订单落 `discount_cents` |

- **为什么**：这些都是"两个状态必须同时成立"的操作。分开做就会出现
  **"退了款、证书还有效"** 这类中间态 —— 那是要出合规事故的。
- **例外**：**发通知、发短信、调 AI、推 CDN 一律不在事务内**（外部依赖会拖住事务），
  改为事务提交后由任务/异步执行。

### 2.2 幂等：**优先靠数据库唯一约束，不靠"先查后写"**

| 场景 | 幂等键 | 落点 |
|---|---|---|
| 下单 | `request_id` + `UNIQUE(student_id, course_id) WHERE status='pending'` | DB |
| 支付/退款回调 | **订单号 + 渠道交易号**（唯一约束） | DB |
| 发证 | `UNIQUE(student_id, course_id, level) WHERE revoked_at IS NULL` | DB |
| 测评开考 | `UNIQUE(student_id, course_id, level) WHERE status='ongoing'` | DB |
| 跑批 | `UNIQUE(stat_date, course_id)` + `ON CONFLICT DO UPDATE` | DB |
| 接口重放 | Redis 幂等键（短 TTL） | Redis（**仅用于挡重复请求，不作为正确性依据**） |

- **为什么**："先查后写"在并发下必然漏（两个请求同时查到"不存在"）。
  **唯一约束是唯一可靠的幂等**；Redis 只是减少无效写入。

### 2.3 回调处理：**先落库，后处理**

```
渠道回调 → 验签 → 金额二次核对 → 【事务】写流水 + 改单 + 开通权益 → 返回 200
                                                    ↓ 事务提交后
                                   异步：发通知 / 发短信 / 写统计
```
- **为什么**：回调有超时与重试；**在回调里做耗时操作会让渠道重试、放大重复**。
  **先返回 200**（表示"我收到了"），后处理失败由**任务补偿**，而不是让渠道重推。

### 2.4 状态机集中：**合法跃迁写成一张表，禁止散落 if**

- 三处状态机：**课程七态** · **订单四态** · **测评会话三态**（+ AI 草稿九态）。
- 实现口径：每个状态机一个 `transitions` 表（`from → to → 条件 → 副作用`），
  **业务只调用 `Transit(from,to)`**，非法跃迁统一返回 `409`。
- **为什么**："这个状态下能不能做那件事"如果散在十几个 `if` 里，**改一条规则要全局搜**，
  而且一定会漏一处（本项目已经因为状态混在一起返工过一次，见 PRD §7.2 B-8 的由来）。

### 2.5 出站脱敏：**双保险**（白名单 DTO + 日志过滤器）

- 序列化层：**教师端与管理员端一律用白名单 DTO**，**禁止直接返回数据库实体**
  （返回实体 = 迟早漏字段）；`id_card` / `phone` 相关字段**在 DTO 里根本不存在**。
- 日志层：访问日志与错误上报**统一过滤器**，把 18 位身份证号与 11 位手机号拦掉。
- **为什么**：单靠一层必然有一天被绕过（新增接口忘了套 DTO、或 `%+v` 打了个结构体）。
  两层是"防漏"而不是"重复劳动"。

### 2.6 审计统一入口：`platform/audit`

- **只允许一个写入口**：`audit.Write(ctx, actor, action, target, before, after)`。
- 覆盖：退款 / 撤证 / 改价 / 下架 / 停用 / 看全号（`reveal`）/ 广播 / 对外内容发布 /
  运营位变更 / 风控动作 / 导出。
- **为什么**：审计的价值在于**字段齐、格式一致、不会被忘**。
  各处自己 insert 的结果就是"关键那一次忘了写"。

### 2.7 时间只从 `platform/clock` 取

- 业务代码**不直接调 `time.Now()`**，统一走 `clock.Now()`（测试可注入）。
- ⚠️ **测评剩余时间、离线有效期、优惠码有效期、订单超时一律以服务端时间为准**（PRD §7.7 C-7）。
- **为什么**：一是可测，二是"客户端时间不可信"这条要落到代码里，而不能只写在文档里。

### 2.8 金额只用 `int64` 分，且**只有一个计算函数**

- 类型：`*_cents`（`int64`）；**绝不出现浮点**。
- **唯一的金额计算入口**：`payment.Quote(list, promo) → (list, discount, pay)`，
  订单落库、支付、退款、对账**全部读这三个值**。
- **为什么**：金额一旦出现第二个计算点，就一定会有一天两个地方算出不同的数 ——
  而那时**对账差异**已经产生了。

### 2.9 AI 网关：**业务只认别名**

```
业务代码 ──(别名 assistant.fast / assistant.strong)──▶ platform 里的 AI 网关
                                                      ├─ 输入审核
                                                      ├─ 检索知识库（限定 course_code）
                                                      ├─ 模型路由（主 / 兜底切换）
                                                      ├─ 引用校验（无引用不给学生）
                                                      └─ 留痕：model / model_version / filing_no / token / 耗时
```
- **为什么**：换模型要能**只改配置**；而"引用校验"和"合规留痕"是**规则**，
  放在网关里做一次，比让 17 个模块各做一次靠谱（PRD §11.3 / M4 文档）。

### 2.10 同步器 `sync`：**两处过滤，只读覆盖**

| 写什么 | 规则 |
|---|---|
| `upstream` 课程 | **只读覆盖**（课程 / 讲次 / 资源清单 / 题库 / 合格线 / 证书名） |
| `platform` 课程 | **绝不触碰**（按 `course.source` 过滤） |
| `ai_assisted` 讲次 | **绝不触碰**（按 `lecture.origin` 过滤） |
| 平台自有数据 | **绝不写**：课程码 / 专业 / 价格 / 权益 / 订单 / 对外内容 |

- ⚠️ **两个过滤条件都必须有**，且要有**专门的回归测试**（"跑完 sync，平台课与 AI 增补讲次必须还在"）。
- **为什么**：这是本项目**最容易被写错的一处**（把 platform 课当成"上游删掉的课"清空）。

## 3. 请求生命周期（中间件顺序）

```
请求 → ① 请求 ID → ② 访问日志(脱敏) → ③ 限频 → ④ 鉴权 → ⑤ 角色/归属校验
     → ⑥ 幂等（写操作）→ ⑦ 业务处理 → ⑧ 白名单序列化 → ⑨ 响应
```

- **③ 限频在 ④ 鉴权之前**：限频要能挡住"未登录的暴力尝试"（登录接口本身就是未登录态）。
  未登录请求按 **IP** 限频，已登录按 **学员 ID** 限频 —— 两者在限频中间件里**同时生效**。
- **⑤ 归属校验**：教师端请求**强制带归属条件**（不是"先查全部再过滤"）；管理员按 `ops/super` 分级。
- **⑥ 幂等只对写操作**；GET 不参与。
- **⑧ 白名单序列化**：教师端与管理员端**必须走 DTO**；学员端返回自己数据时同样过滤敏感字段。

## 4. 任务与调度（**不是消息队列**）

> 结论先行：**首发不引入独立 MQ**（技术选型 v1.2 §10）。异步任务用**表 + 定时触发**即可，
> 幂等键与重试策略见 §2.2。**量级上来后（压测证明）再换**，业务代码不改。

| 任务 | 触发 | 幂等键 | 失败处理 |
|---|---|---|---|
| **对账** | 每日（可配时点） | `UNIQUE(reconcile_date, channel)` | 差异 ≠ 0 → **P0 告警**；生成差异明细 |
| **T+1 统计跑批** | 每日凌晨 | `UNIQUE(stat_date, course_id)` | 重跑幂等（`ON CONFLICT DO UPDATE`） |
| **AI 运营周报** | **每周一**（随跑批） | `UNIQUE(course_id, week)` | 失败不阻塞其他课程 |
| **知识库重建** | 手动触发 / 课程内容变更后 | `course_code + checksum` | 失败保留旧索引（**不删旧的再建**） |
| **离线授权过期清理** | 每日 | `expires_at < now` | 只改状态，不删记录 |
| **运营位到期下线** | 每小时 | `ends_at < now AND status='active'` | 只改状态 |
| **优惠码过期** | 每小时 | `valid_to < now AND status='active'` | 只改状态 |
| **订单超时关闭** | 每分钟 | `expired_at < now AND status='pending'` | 复用幂等关闭接口 |
| **通知/短信发送** | 事务提交后投递 | 业务键去重 | 重试 + 告警（**不在业务事务里**） |

- **调度实现**：`cmd/server` 内起一个**单实例调度器**（定时器 + 分布式锁，锁用 Redis），
  **不做独立调度服务**（少一个组件）。【M1 细化：锁的粒度与超时】

## 5. 外部依赖的接入位置（**业务不直连**）

| 依赖 | 适配器位置 | 业务侧只看到什么 |
|---|---|---|
| 支付（微信 / 支付宝） | `payment/gateway` | `Prepay` · `Query` · `Refund` · `VerifyNotify` |
| 大模型 | `aigateway` | `Answer(alias, ctx)` / `Generate(draft_ctx)` |
| Embedding | `aigateway/embed` | `Embed(texts)`（**与主模型同栈**） |
| 短信 | `platform/sms` | `Send(template, phone, params)` |
| 内容安全 | `platform/security` | `Check(text) → {pass, hit}`（输入输出双向） |
| 对象存储 / CDN | `platform/cos` | `SignURL(assetId, ttl)` |
| 制证（PDF） | `cert/render` | `Render(certNo) → bytes`（Chrome headless，**串行 worker**） |
| 图形验证码 | `platform/captcha` | `Issue/Verify` |

- **一条纪律**：**每个适配器都要有"未配置时的行为"** ——
  除强制密钥外，其余**未配置即该功能 fail-closed**（返回明确的业务错误，而不是 500）。
- **凭据**：全部经 `shared/.env` 注入（`deploy/.env.example` 是模板），**业务层不接触凭据原文**。

## 6. 错误码 → HTTP 的统一映射

| 场景 | HTTP | 说明 |
|---|---|---|
| 参数错误 | 400 | `10xxx` |
| 未登录 / 会话失效 | 401 | |
| 无权限（角色不够） | 403 | **越权一律 403**，不返回 404 掩盖 |
| 资源不存在 | 404 | **证书已撤销时 `/me/certs/{certNo}/file` 返回 404**（不暴露"曾存在"） |
| **状态冲突**（非法跃迁） | **409** | 订单/课程/测评状态机非法跃迁统一 409 |
| 幂等冲突（重复下单等） | 200 + 复用既有对象 | **不是错误**：返回同一订单号 |
| 限频 | 429 | `10903` |
| 依赖不可用（支付/AI/短信） | 503 | **fail-closed**，且**如实说明哪一项不可用** |

- **为什么单列 200-复用**：连点下单与弱网重试**都是正常行为**，回 4xx 会让前端以为失败。

## 7. 内容资产与分发（开发期 vs 生产）

| 项 | 开发期 | 生产 |
|---|---|---|
| 课程资产（讲义 / 课件 / 音视频 / 冻结输出） | **本地目录**（`CWTC_CONTENT_SOURCE` 指向上游资产） | **COS + CDN**，签名 URL 短时有效 |
| 数据库 | 本地 PG（**需 pgvector**）+ 本地 Redis | 云上（不对公网开放） |
| 迁移 | `make migrate`（本地） | 发布流水线内执行，**先迁移后切换** |
| 制证 | 本地 Chrome headless | 服务器 Chrome headless（**离线安装，不走外网**） |

- **为什么双轨写清**：开发期依赖 COS 会让"新同学跑不起来"；生产依赖本地文件会让"发布即 404"。
  **切换点只在一个配置项**。
- **资产清单**来自上游（附录 A）；`sync` 负责把清单落库，**文件本体按上面的双轨取**。

## 8. 测试策略（与门禁对齐）

| 层 | 做法 | 门禁 |
|---|---|---|
| 单元测试 | 表驱动；**状态机/金额/幂等/脱敏/权限**必须有专测 | 覆盖率 ≥ 80% |
| 契约测试 | 错误码、信封、分页、字段白名单 | `rolecheck` / `publiccheck` |
| 端到端脚本 | **两条关键链路**：下单→支付回调→解锁；交卷→判分→发证 | M2 / M3 验收物 |
| 一致性脚本 | `sync --check`（资源齐备 + 题库无重复编号） | CI |
| 合规脚本 | `scan-sensitive.sh` · `scan-claims.sh` · `audit_prd_closure.py` | CI |

- **一条纪律**：**门禁必须自己验证一次**（故意造一个失败样例，确认它会红）。
  没验证过的门禁等于没有门禁 —— 本项目在 `audit_prd_closure.py` 上做过这个动作。
