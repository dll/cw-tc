## 4. 第一天跑起来（环境与密钥）

```bash
# 1) 后端：先造三把强制密钥（缺失则服务拒绝启动，这是设计如此）
#    ⚠️ 校验的是**字符串长度**：ENC 必须**恰好 32 个字符**，HMAC / SESSION **≥32 个字符**。
#    `openssl rand -base64 24` → 恰好 32 字符；`openssl rand -hex 16` 亦可。
#    （`openssl rand -hex 32` 会得到 64 字符 —— **服务会拒绝启动**，已实测。）
export CWTC_ID_CARD_ENC_KEY=$(openssl rand -base64 24)      # AES-256-GCM，恰好 32 字符
export CWTC_ID_CARD_HMAC_KEY=$(openssl rand -base64 24)     # HMAC-SHA256，≥32 字符
export CWTC_SESSION_SECRET=$(openssl rand -base64 24)       # 会话签名，≥32 字符
cd packages/server && make build && make test               # 产出 bin/cw-tc-server
# 实测（2026-10-05）：三把 32 字符键齐备时 → 「配置已加载 / 服务启动 version=dev」，路由注册成功

# 2) 数据库：开发/测试用 SQLite —— **无需安装任何数据库服务**
export CWTC_DB_DRIVER=sqlite          # 生产改为 postgres（且 DEPLOY_ENV=production 时必须为 postgres）
cd packages/server && go test ./migrations/... -count=1 -v   # 内存库真跑迁移（含幂等与外键检查）

# 3) 前端
cd packages/app   && flutter pub get && flutter analyze && flutter test
cd packages/admin && npm install      && npm run typecheck && npm run test

# 4) 门禁（提交前跑一遍，与 CI 同口径）
bash deploy/scripts/scan-sensitive.sh && bash deploy/scripts/scan-claims.sh
python tools/audit_prd_closure.py
```

> 环境变量逐项含义见 `deploy/.env.example`（含未配置时的 fail-closed 行为）。
> **别把真实密钥提交进仓库**（`scan-sensitive.sh` 与 gitleaks 会拦）。

## 5. 本轮为"准备度"补强的东西（自证修复）

开工前做了一次**门禁自证**：查出的问题**都不是"缺功能"，而是"看起来通过了、其实没干活"或"文档写错了会挡人"**。
共 4 个"门禁假装在工作" + **3 个会让 CI / 启动直接失败的真实缺陷**（都是**实跑**才发现，通读文档看不出来）。

| # | 问题 | 性质 | 修法 |
|---|---|---|---|
| 1 | `scan-claims.sh` 用 `xargs -0 cat` 遍历源码，**本机因"环境块过大"exec 失败**，失败被管道吞掉 → **学生端 / 管理端 UI 文案整目录没被扫** | **静默漏扫**（合规门禁） | 改 **shell 循环**（不 exec 外部进程）；并**每次打印"实际读到 N 字符 / M 个文件"**；读到 0 字符即判失败 |
| 2 | `audit_prd_closure.py` 的"陈旧版本号"检查把边界锚在 `版本历史`，而该词**在 §0 第 80 行就出现过** → 边界提前到文首，**对 PRD 整体空转** | **静默空转** | 边界改锚 **`## 附录 C`**；现在能抓到 §13 的旧版本号 |
| 3 | 审计读版本号的正则要求 `**` 紧跟数字，而技术选型写作 `**v1.2（增量修订）**` → **读不到 → 检查空转** | **静默空转** | 放宽正则；并新增"**版本号读取失败**"本身作为致命项（读不到就报错，不再假装通过） |
| 4 | README「铁律（共 8 条）」而 AGENTS 实为 **15 条**；docs/README「166 个接口」按它自述的命令实为 **184**；PRD 头部版本字段还写着 **v2.12** | **文档自述失真** | 逐处改正；并把这些**带"出处/派生"的自述数字**纳入审计 |
| 5 | `packages/app/test/widget_test.dart` 有一处 `unused_import`（**warning 级**） | **会让 CI 的 `flutter analyze` 直接红** | 删除该 import；复跑 `No issues found` |
| 6 | `packages/admin` 缺 `@types/node`，且 tsconfig 的 `types` 把全局类型限死 | `npm run typecheck` 报 `TS2307`（`node:url`），**CI 会红** | 加 `@types/node` devDep + `types` 补 `node`；复跑 `TYPECHECK_EXIT=0` |
| 7 | `deploy/.env.example` 与 README 写「32 **字节**」，而 `config.go` 校验的是**字符串长度 == 32** —— 按"base64(32 字节)"填会得到 44 字符 → **服务拒绝启动** | **"第一天跑起来"会被直接挡住** | 文档口径改为「**恰好 32 个字符**」并给出 `openssl rand -base64 24`；实测 32 字符键可正常启动 |

**教训（已写进门禁注释）**：**门禁必须能自证"我扫过东西"** ——
读到 0 字符、读不到版本号、正则不匹配，都要**显式失败**，而不是安静地报"通过"。
**一个永远返回 0 的门禁，比没有门禁更危险**，因为它会让人停止怀疑。
