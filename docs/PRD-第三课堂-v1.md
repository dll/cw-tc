## 1. 第三课堂是什么

### 1.1 三个课堂的由来

| | 第一课堂 | 第二课堂 | **第三课堂（本产品）** |
|---|---|---|---|
| 形态 | 线下、传统课堂 | 学校开设的第二课堂 | **在线、AI 驱动** |
| 组织者 | 任课教师 | 学校 / 团委 / 社团 | **平台 + AI** |
| 激励 | 学业成绩、学分 | **学分**、综测 | **企业认证证书** |
| 时空 | 固定（课表） | 半固定（活动排期） | **完全自主（随时随刻）** |
| 进度 | 统一 | 统一 | **自适应、自定进度** |
| 内容来源 | 教师讲授 | 学校组织 | **AI 生成 + 教师审定 + 机器验真** |
| 评价 | 教师主观 + 期末考 | 参与记录 | **即测即评（机器判分 + 人工采点）** |
| 证书 | 无 | 无（记学分） | **畅网智能科技颁发，编号可验真** |

**它不是"把线下课录成视频放到网上"**，而是三件事的重新组合：

1. **把"教"交给 AI 与课程资产**（教师从"讲授者"变成"审定者"）；
2. **把"学"交还学生**（自选课程、自定节奏、自定深度）；
3. **把"证"接入产业**（不是学校发的学分，而是**企业发的、行业认的能力认证**）。

### 1.2 官方定义（用于对外）

> **第三课堂**是以 AI 为引擎、对第一课堂（线下传统课程）与第二课堂（学校第二课堂）
> 进行改造的自主学习教育平台。它由 **AI 生成并维护课程内容**，学生**自主选择典型课程学习**、
> **在线完成分级测评**，通过后由 **畅网智能科技有限公司颁发能力认证证书**。
> 全程实名（身份证号注册），证书编号可公开验真。

### 1.3 关键取向：**以典型课程为主，其它讲座为辅**

这是本产品的**内容结构原则**，不是技术选择：

- **典型课程（主线）**：体系完整、有实验、有真机实测数据的课程。
  学生沿"讲 → 练 → 测 → 证"走完整条路。
  当前典型课程（按就绪度）：
  **03-CF（C 语言，15 讲）· 05-OS（操作系统，22 讲）· 07-CN（计算机网络，17 讲）·
  06-CP（编译原理，16 讲）· 08-CC（计算机组成原理，16 讲）· 04-DB（数据库，10 讲）**。
- **讲座 / 专题（辅线）**：单点知识、案例复盘、行业视角。
  不单独发证，但可作为主线的补充阅读与扩展题。
  当前辅线：**02-DO（软件工程 · DevOps 案例课，10 单元）**，以及各课的"综合篇 / 收官讲"。
- **学习路径**：主线是"能发证的正课"，辅线是"看得懂、考不着证但加深理解"的讲座。
  **一个学生可以只走一条主线拿到一张证，也可以横向跨课凑齐多张证。**

## 2. 第三课堂的十大特色（**本产品的立身之本**）

> 这十条是"为什么要有第三课堂"的答案，也是本 PRD 后面所有功能需求的**来源**。
> 每条给出：**是什么 → 凭什么成立 → 落到产品上是什么功能**。

### 特色一：**AI 是引擎，不是噱头**

- **是什么**：课程内容、练习题、解析、判分规则由 AI 大规模生成，**但关键判据由人拍板**。
- **凭什么成立**：上游 8 门课程已经跑通"**AI 起草 → 人定判据 → 机器验真**"的流水线，
  累计产出 **19 份 AI 草稿 / 3827 行**，其中**主动留空 27 个常数等人工填写** ——
  证明这套协作范式**已经落地过**，不是设想。
- **产品功能**：内容管理后台的"AI 草稿区"（原始稿与人工稿**并存、可对照**）、
  每条内容的"来源标注"（AI 生成 / 人审定 / 真机实测）。

### 特色二：**数字必须真、口径必须写明**（全系列铁律）

- **是什么**：平台展示的每个数字，都必须能追到出处；范围优于单点；测不出的**标【未取到】**。
- **凭什么成立**：上游课程有四类数字标注（【实测】【真机读数】【协议常数】【他方实现】），
  且有 `_range.py` 报范围、`_verify.py` 判据、冻结输出文件可逐字核对。
  题库中 **1204 道题**的参考答案，数字均可在课程冻结输出里找到出处。
- **产品功能**：内容区强制"证据链"字段（数字 → 出处 → 类别）；
  测评解析里保留"口径说明"；**未取到的地方就写未取到**，后台有一键检查。

### 特色三：**即测即评，客观题机器判**

- **是什么**：学完就测，单选/判断/填空**当场出分**；主观题给"待人工阅卷"清单。
- **凭什么成立**：7 门课都配了 **`_grade.py` 自动判分程序**，
  **523 道客观题**可自动判分，且**每门都能自检满分**
  （拿标准答案当答卷，必须 100% 对，`--self-test` 全过：02-DO 114 · 03-CF 130 ·
  04-DB 47 · 05-OS 54 · 06-CP 56 · 07-CN 63 · 08-CC 59）。
- **产品功能**：在线答题 → 客观题实时判分 → 主观题进入采点队列；
  **填空标为"半自动"**（宽松匹配，必须抽查，界面明示）。

### 特色四：**分级测评，能力可分层**

- **是什么**：每门课三档 —— **L1 通识 / L2 工程师 / L3 架构师**，对应三张不同的证书。
- **凭什么成立**：题库已按 L1/L2/L3 组织，**合格线统一**
  （L1 60/75/90 · L2 70/82/92 · L3 80/90/96），且每档题型不同：
  L1 考"是什么"，L2 考"算得出、读得懂"，L3 考"做设计、定责任、做取舍"。
- **产品功能**：学生可**逐级考**（推荐）或**跳级考**（需满足前置）；
  成绩单按 L1/L2/L3 分别记档（合格 / 良好 / 优秀）。

### 特色五：**企业颁发、编号可验真的证书**

- **是什么**：通过测评 → 生成正式证书（PDF）→ 编号可公开查真。
- **凭什么成立**：证书模板、编号规则、制证脚本**已经齐备并跑通过**：
  编号规则 `CW-{课程码}-{级别位}{年份}{流水号6位}`（例 `CW-CN-M202600137`），
  7 门课各有 **三档空白模板 + 合订预览 + 虚构样例**，且**布局校验全过**。
- **产品功能**：自动判证 → 生成 PDF → 分配编号 → 写入"证书台账" →
  提供**公开验真页**（输入编号 → 显示"真实 / 已撤销 / 不存在"）。

### 特色六：**实名制，身份与证书绑定**

- **是什么**：学生用**身份证号**注册，证书与真实身份绑定，**一生一号一证**（同课同级不重复颁发）。
- **凭什么成立**：证书上本就印有身份证号；上游题库的 `保密说明.md` 已明确
  **默认脱敏**（前 6 + 8×星号 + 后 4），`CERT_ID_MODE=full` 才印全号。
- **产品功能**：注册即实名核验（格式 + 校验位）；证书默认脱敏打印；
  详见 **§9 安全与合规**（身份证号属个人敏感信息，本节是本产品的红线）。

### 特色七：**多课程矩阵，横竖都能走**

- **是什么**：7 门课形成矩阵 —— **竖着走**是"一门课由浅到深（L1→L3）"，
  **横着走**是"多门课各拿一张证"。
- **凭什么成立**：课程资产已经统一（见 §6），题库 schema、证书命名、合格线**全部一致**，
  所以"多课一平台"不是愿景，是**现成的**。
- **产品功能**：课程广场（按主线/辅线筛选）、个人"能力地图"（哪几门拿了证、到哪一级）。

### 特色八：**自主学习，路径自己拼**

- **是什么**：没有课表、没有排期。学生自定"学哪门、学到哪一级、什么时候考"。
- **凭什么成立**：每讲资源自足（课件 / 讲义 / 口播稿 / 配音 / 实验 / 冻结输出 / 思考题），
  且平台提供**可选的推荐路径**（不是强制的进度条）。
- **产品功能**：学习路径推荐（如"零基础 → 03-CF L1 → 07-CN L1"）、
  断点续学、错题本、**可选**的每日目标（不设强制签到）。

### 特色九：**资源即资产，全部可核对**

- **是什么**：每个数字、每段结论都能对到一份**冻结输出文件**（真机跑出来的）。
- **凭什么成立**：以 07-CN 为例，讲级资源含 **25 份课件 / 118 份 Markdown / 133 个代码文件 /
  45 份冻结输出 / 374 条配音**；全平台合计 **1204 题 / 7916 分**。
- **产品功能**：内容详情页可直接"查看原始输出"（把冻结输出渲染在同一页），
  学生看到的不只是结论，还有**结论是怎么跑出来的**。

### 特色十：**可交接、可复现、可持续**

- **是什么**：AI 生成的内容**不是黑箱** —— 换个人接手，能跑、能改、能重制。
- **凭什么成立**：上游全部课程都有"**生产管线交接手册**"、`_ai_draft/` 原始稿一字未改、
  每讲有使用说明 / 思考题 / 接续说明，且**资源体检工具**（`_audit_resources.py`）证明
  7 门课资源**全部备齐**。
- **产品功能**：后台"内容体检"面板（资源齐备度、题库一致性、证书模板完整性一键自检）。

## 3. 目标用户与画像

### 3.1 用户角色

| 角色 | 是谁 | 核心诉求 | 主要动作 |
|---|---|---|---|
| **学员**（C 端） | 在校生、自学者、转行者 | 学到真东西、拿到能证明的证书 | 选课 → 学 → 测 → 领证 |
| **助教 / 阅卷人** | 教师、研究生助教 | 高效批主观题、看班级学情 | 采点阅卷、导出成绩 |
| **课程管理者** | 刘老师 / 教研 | 上架课程、管题库、管证书 | 内容管理、证书台账 |
| **企业 / HR**（外部） | 招聘方 | 验证候选人证书真假 | 验真页查编号 |
| **系统管理员** | 运维 | 稳、安全、可回滚 | 部署、监控、备份 |

### 3.2 典型画像

**画像 A：大三学生 · 小林（主线学习者）**
- 想补"计算机网络"，但线下课进度固定、听不懂的地方没法倒回去。
- 用第三课堂：选 07-CN，从 L1 开始，每讲看完课件做 5 道题，
  卡在第 3 讲讲义的"CRC"上 → 看回放、看冻结输出 → 继续。
- 一周后考 **L1** 通过（78 分，良好）→ 拿到《计算机网络通识能力认证》。
- 两个月后考 **L2**，通过（85 分）→ 拿到《计算机网络工程师认证（中级）》。

**画像 B：已工作者 · 阿哲（横向跨课者）**
- 面试被问"TCP 三次握手"，答得含糊。想系统补，但没时间上整门课。
- 用第三课堂：直接考 07-CN 的 L2 摸底 → 发现有盲区 → 回到对应讲学习 → 重考。
- 同时横向考了 03-CF L1、04-DB L1，一个月拿到三张证。

**画像 C：助教 · 王老师（阅卷者）**
- 负责 05-OS 的 L2 主观题。
- 用第三课堂：后台看到 42 份待阅卷 → 按"评分要点"逐条采点 →
  系统按采点自动算总分与分档 → 一键发证。

## 5. 产品目标与成功指标

### 5.1 目标（v1.0）

1. **跑通闭环**：一个学生，从注册到拿到第一张证书，**全流程无人工介入**（客观题路径）。
2. **覆盖全部典型课程**：7 门课（01-4C 暂缓）的 L1/L2/L3 全部可学、可测、可证。
3. **证书可信**：编号唯一、可验真、可撤销。
4. **可上线**：部署到 `cw-tc.ccit-agent.cn`，可被真实学生使用。

### 5.2 成功指标（North Star 与护栏）

| 类型 | 指标 | v1.0 目标 |
|---|---|---|
| **北极星** | 完成"注册 → 至少 1 张证书"的学员数 | — （上线后 30 天观测） |
| 转化 | 注册 → 开始学习 | ≥ 70% |
| 转化 | 开始学习 → 参加至少一次测评 | ≥ 40% |
| 质量 | 客观题判分准确率 | **100%**（自检满分是硬门禁） |
| 质量 | 证书编号重复率 | **0** |
| 性能 | 首屏（课程广场）加载 | ≤ 2 s（P75，4G 网络） |
| 性能 | 客观题提交到出分 | ≤ 1 s（P95） |
| 可用性 | 月度可用率 | ≥ 99.5% |
| 合规 | 身份证号明文落库 | **0**（必须加密/脱敏） |

## 7. 功能需求（**模块级**）

> 标记约定：`[P0]` 首发必须 · `[P1]` 首发后补 · `[P2]` 远期。
> 每条需求给出**验收标准**（可测）。

### 7.1 账号与实名（模块 A）

#### A-1 `[P0]` 实名注册

- **输入**：真实姓名 + **身份证号** + 手机号 + 短信验证码。
- **处理**：
  1. 身份证号**格式校验 + 校验位校验**（GB 11643-1999 加权校验，本地可算，不依赖第三方）；
  2. 手机号短信验证；
  3. 生成**学员号**（如 `TC2026-000137`，与身份一一对应，**不可改**）；
  4. 记录**同意条款**的时间戳与版本号（合规留痕）。
- **验收**：非法身份证（校验位错）必须被拒；同一身份证号**不允许重复注册**；
  注册成功后立即可登录，无需人工审核。

#### A-2 `[P0]` 登录与身份核验

- **方式**：手机号 + 验证码（默认）；可选密码。
- **验收**：连续错码 5 次锁定 10 分钟；登录态有效期 ≤ 7 天；支持主动登出全部设备。

#### A-3 `[P1]` 实名信息的查看与更正

- **可改**：手机号、联系方式。
- **不可改**：姓名、身份证号 —— 需走"**人工申诉**"（防止盗用身份）。
- **验收**：身份证号一旦登记，**任何接口都不得返回明文**（见 §9）。

### 7.2 课程与学习（模块 B）

#### B-1 `[P0]` 课程广场

- **展示**：课程卡片（名称 / 类型 / 讲数 / 题量 / 三档证书名 / 是否主线）。
- **筛选**：主线 / 辅线 / 全部；按就绪度排序。
- **数据源**：`课程总览.json` 的 `courses[]`（**动态读取，不写死**）。
- **验收**：课程列表与 `课程总览.json` 完全一致；新增课程只需更新 JSON + 资源，**不改前端代码**。

#### B-2 `[P0]` 课程详情与讲次导航

- **展示**：课程简介、三档证书说明、讲次列表（可展开）。
- **每讲**：标题、资源清单（课件 / 讲义 / 视频 / 音频 / 实验 / 冻结输出 / 思考题）。
- **验收**：**未拥有的资源（如某课无视频）不显示空位**；点击资源可打开/下载。

#### B-3 `[P0]` 资源查看器

- **HTML 课件**：**App 端必须走 WebView**（`flutter_inappwebview`），Web 端走 iframe。
  原生渲染无法还原课件的动画与节拍，**这是硬约束**（见 §11.3）。
- **Markdown**：渲染为网页（代码高亮、表格）。
- **音频/视频**：App 端原生播放器（倍速、断点、后台播放）；Web 端浏览器播放器。
- **冻结输出**：等宽渲染，**保留原始换行**（数字可对账）。
- **验收**：大文件（>10 MB 的 HTML）不卡死；音频播放位置可记忆；
  **跨端口径 —— 正文与数字必须一致，表现允许有差异**。

#### B-4 `[P0]` 我的课程 / 断点续学

- **加入我的课程**：收藏课程，记录进度。
- **进度**：以"讲"为最小单位（已看/未看），可手动标记。
- **验收**：换设备登录，进度**不丢**（服务端存储）。

#### B-5 `[P1]` 学习路径推荐

- **推荐规则**（示例，可配置）：
  - 「零基础」→ 03-CF L1 → 07-CN L1 → 04-DB L1
  - 「后端方向」→ 03-CF L2 → 05-OS L2 → 07-CN L2
- **验收**：推荐为**建议**而非强制；学生可忽略并自由选课。

#### B-6 `[P2]` 错题本与笔记

- 错的题自动进错题本；支持手动记笔记（仅本人可见）。

### 7.3 测评与判分（模块 C）

#### C-1 `[P0]` 在线答题

- **题型支持**：单选、判断、填空、名词解释、简答、计算、代码阅读、编程、实验设计、对比分析、系统设计、故障归因、选型评审、综合论证。
- **组卷**：从 `题库.json` 按等级抽题（见 C-2）。
- **交卷**：客观题即时判分；主观题入"待阅卷"队列。
- **验收**：断网重连不丢答案；交卷后不可再改（但成绩单可查）。

#### C-2 `[P0]` 组卷策略（按等级）

| 等级 | 卷面组成（参考上游 README） | 满分 |
|---|---|---|
| L1 | 单选 20 + 判断 10 + 填空 6 + 名解 3 + 简答 6 | 100 |
| L2 | 计算 4 + 工件阅读 2 + 实验设计 2 + 对比分析 2 | 100 |
| L3 | 系统设计 1 + 选型评审 1 + 综合论证 1 + 故障归因 1（+ 跨章综合） | 100 |

- **可组卷套数**：由题库实时计算（**按题型逐项算、取最紧的一项**，不按总题数）；
  当某题型不足以出新卷时，**界面明示"本档当前可组 N 套"**。
- **验收**：同一学生重考时**优先避开已做过的题**（在题量允许时）。

#### C-3 `[P0]` 客观题自动判分

- **复用上游 `_grade.py` 的判分规则**：
  - 单选：严格匹配（容忍大小写/全角）；
  - 判断：对/错（另接受 √ × T F true false 1 0）；
  - 填空：**宽松匹配 + 按空给分**（整串 / 去括号主干 / 括号内备选均接受）。
- **硬门禁**：上线前必须**移植并跑通 `--self-test`**（标准答案必须满分）。
- **验收**：**填空在界面明确标注"半自动，需抽查"**；判分日志可追溯（哪题判对/判错）。

#### C-4 `[P0]` 主观题阅卷（采点制）

- **流程**：待阅列表 → 按"评分要点"逐条采点 → 系统累加 → 分档。
- **功能**：双人阅卷（差值超阈值触发第三人）、给分备注、批量操作。
- **验收**：采点项与题目的评分要点**逐条对应**（后端从题库解析出要点条目）。

#### C-5 `[P0]` 成绩与分档

- **分档**：L1 60/75/90 · L2 70/82/92 · L3 80/90/96；L2/L3 叠加单科最低分。
- **成绩单**：显示总分、各题型得分、分档、是否达标、**口径说明**。
- **验收**：分档计算与 `课程总览.json` 的 `bands` **完全一致**。

#### C-6 `[P1]` 重考与补考

- 未达标可重考（次数可配）；记录**每次成绩**（不覆盖历史）。

### 7.4 证书（模块 D）

#### D-1 `[P0]` 自动判证

- **触发**：成绩达标 → 自动判定具备发证资格（不自动发，进入 D-2）。
- **规则**：同"课程 + 等级"**只发一张**（以最高成绩为准）；跨课可多张。
- **验收**：达标即出现在"可领证书"列表。

#### D-2 `[P0]` 证书生成与颁发

- **生成**：复用上游 `_make_certs.py`（HTML 模板 + headless 浏览器 → PDF）。

- **分配编号**：`CW-{课程码}-{级别位}{年份}{流水号6位}` —— **全局唯一，原子递增**。
- **验收**：编号不重复；PDF 生成失败可重试且**不消耗编号**（用事务）。

#### D-3 `[P0]` 证书台账

- 记录每张证书的：编号、学员、课程、等级、成绩、签发时间、状态（有效/已撤销）。
- **验收**：台账可导出 CSV；撤销后原编号**不可重新分配**。

#### D-4 `[P0]` 公开验真页

- **入口**：`https://cw-tc.ccit-agent.cn/verify`（无需登录）。
- **输入**：证书编号。
- **输出**：**真实**（显示课程/等级/姓名脱敏/日期）/ **已撤销** / **不存在**。
- **验收**：**绝不回显完整身份证号**；有防刷限频（见 §9）。

#### D-5 `[P1]` 证书下载与分享

- 下载 PDF；生成分享链接（链接本身不含敏感信息）。

## 9. 安全与合规（**本产品的红线**）

> 本产品采集**身份证号**，属《个人信息保护法》定义的**敏感个人信息**。
> 这一节不是"可选项"，是**上线的前提**。任何一条不满足，都不得对真实学生开放。

### 9.1 数据最小化

| 数据 | 是否采集 | 用途 | 留存 |
|---|---|---|---|
| 姓名 | 是 | 证书署名 | 长期（与证书绑定） |
| **身份证号** | **是（必须）** | 实名 + 证书编号绑定 | 长期（**加密存储**） |
| 手机号 | 是 | 登录、通知 | 长期 |
| 出生日期/性别 | **否** | — | **不从身份证号推导存储** |
| 住址 | **否** | — | — |

**原则**：**校园身份证能证明"是谁"就够了，不采集、不推算、不存储任何多余信息。**

### 9.2 存储要求（硬性）

1. **明文绝不落库**：身份证号入库前加密（推荐 **AES-256-GCM**，密钥由 KMS / 环境变量注入，**不进代码库**）。
2. **另存单向哈希**：`id_card_hash = HMAC-SHA256(id_card, 服务端密钥)`，用于"唯一性判断"，
   **用于防重复注册**——此值不可逆，即使泄露也无法还原。
3. **展示一律脱敏**：默认 `前6位 + ******** + 后4位`（`110101********1234`）；
   全号只在**极少数**场景（如证书打印且用户显式选择）可用于生成，**且不进日志**。
4. **日志脱敏**：所有日志、错误上报、监控埋点，**必须过滤身份证号与手机号**（写正则过滤器 + 单测）。

### 9.3 传输与访问

- **全站 HTTPS**（腾讯云免费证书 + nginx，强制 HSTS）。
- 数据库、缓存**不对公网开放**（安全组只放 80/443 与 22）。
- 后台接口走**独立鉴权**（管理员 Token + 二次验证），操作全部进 `audit_log`。
- **验真页防刷**：按 IP 限频（如 20 次/分钟），**不回显完整身份证号**。

### 9.4 用户权利（必须实现）

| 权利 | 实现 |
|---|---|
| 知情同意 | 注册时明示"采集什么、做什么用、存多久"，**勾选同意**（版本化留痕） |
| 查询 | 个人中心可看自己的实名信息（脱敏）与全部证书 |
| 更正 | 手机号可自助改；姓名/身份证走人工申诉 |
| 删除 | **注销账号**：证书依法留存（编号台账），**身份信息可匿名化**，需人工审核 |
| 撤回同意 | 支持，撤回后停止使用相应信息（已发证书仍可按编号验真） |

### 9.5 证书颁发的合规边界

- 证书**必须**标明：颁发主体（畅网智能科技有限公司）、课程、等级、成绩、编号、签发日期。
- **不得**暗示"国家认证""官方资格"；证书是**企业能力认证**，非学历、非职业资格。
- 已签发证书进**独立台账**；模板与已签发件**不放入公开代码库**

### 11.2 技术选型

| 层 | 选型 | 理由 | 状态 |
|---|---|---|---|
| 后端 | **Go 1.26 + Gin** | 与 CCIT / TSLOMS 同一套规范；并发好、部署简单（单二进制） | 推荐（沿用） |
| 数据库 | **PostgreSQL 15+** | 事务可靠（证书编号必须原子）；JSONB 存题目快照 | 推荐 |
| 缓存 | **Redis** | 会话、验证码、限频 | 推荐 |
| **学生端（多端）** | **Flutter 3.22+（Dart 3.4+）** | 一套代码出 **Android / iOS / Web**，**多端一致**（自绘引擎）；与 ccit（Flutter Web）、wxx（Flutter 六端）同栈 | **已定**（见 §11.3） |
| **管理端** | **Vue 3 + Vite + Element Plus + Pinia** | 表单/表格密集、桌面优先；沿用 `tsloms/packages/admin` 现成规范 | **已定**（见 §11.3） |
| 静态资源 | **腾讯云 COS + CDN** | 课件/视频/音频多、体积大 | 推荐 |
| 制证 | **Chrome headless（Puppeteer 或 Playwright）** | 复用上游 `_make_certs.py` 的 HTML→PDF 路线 | 推荐（沿用） |
| 部署 | **Docker Compose + systemd + nginx** | 沿用 cw-vopc / ccit 约定 | 推荐（沿用） |
| CI/CD | **GitHub Actions → SSH 发布** | 已有成熟模板 | 推荐（沿用） |

### 11.3 前端选型（**已定：Flutter 多端 + Vue 管理端**）

> **前置约束（刘老师 2026-10-03 明确）**：第三课堂**多端一致**，**移动应用为主，Web 应用为辅**。
> 完整论证见 **`docs/技术选型-v1.md`**，此处只给结论与边界。

| 端 | 选型 | 定位 |
|---|---|---|
| **学生端（主战场）** | **Flutter 3.22+（Dart 3.4+）** | 单代码库输出 **Android / iOS / Web**；鸿蒙为**可选**目标 |
| **管理端** | **Vue 3 + Vite + Element Plus + Pinia** | 阅卷台 / 内容管理 / 证书台账，**桌面优先** |
| **对外静态页** | **Go 模板直出** | 验真页 `/verify`、隐私政策、用户协议（**不走 Flutter Web**，保 SEO 与首屏） |

**为什么不是别的**（既有工程资产实测，非推测）：

- **ccit** 前端 = Flutter Web（`packages/web/pubspec.yaml` → `ccit_web`）；
  **wxx** 前端 = Flutter 六端（`android/ios/linux/macos/harmonyos/web`）+ **独立原生小程序**；
  **tsloms** 管理端 = Vue 3 + Element Plus（`tsloms-admin`）。
  → 本题的答案是**既有事实**，选它不是偏好，是**一致性成本最低**。
- "多端一致"是 Flutter 的自绘引擎本职工作；"移动应用为主"要求**非套壳 H5**（可上架、可推送、可离线）。
- **Web 为辅 → Flutter Web 的 SEO 短板在本产品不成立**：课程页是登录后的功能页，
  唯一需要被搜索引擎抓的验真页由 Go 模板直出（见上表）。

**多端一致的真实边界**（"一套代码"≠"零分叉"，差异是设计内的）：

| 项 | App 端 | Web 端 |
|---|---|---|
| HTML 课件（含动画/节拍） | **必须 WebView** | iframe |
| 音频/视频 | 原生播放器（后台播放、倍速、记忆位置） | 浏览器播放器，后台受限 |
| 离线缓存 | 支持（弱网刚需） | 浏览器缓存 |
| 布局 | 手机单栏 + 底部导航 | 宽屏多栏 |
| 推送 | 系统推送 | 站内消息 |

> **验收口径**：同一功能在两端**正文与数字必须一致**；**表现（布局/播放器）允许有差异**。

**风险（如实标注）**：Flutter Web 首屏体积较大（CanvasKit + 中文字体），
**本机未实测** —— §10.1 的 Web 首屏指标**待上线前实测后重定，不沿用 2 s 假设**。

### 11.4 与上游的接口（**只读同步**）


```
   │
```
