## 〇、结论先行（四句话）

1. **选型定案**：**阿里云百炼（通义千问 Qwen 系列）为主**，**火山引擎（豆包 Doubao 系列）为兜底 / 双活**，
   **Embedding 与主模型同厂商**，**内容安全用云厂商服务 + 自建课程词表**。
2. **备案路径定案：走"登记"，不走"备案"** —— 依据是"**通过 API 接口或其他方式直接调用已备案模型能力**"的，
   **由地方网信办开展登记**（国家网信办公告原文）。备案是自研 / 二次开发者的事，**我们不是**。
3. ⚠️ **因此有一个必须守住的决策：首发不做微调**。
   **微调 = 实质性二次开发 → 从"登记"升级为"备案"**（省级初审 + 国家终审，**周期是 6~8 个月量级**）——
   为了让 AI 更贴合课程，换掉一个上线时间，账不划算。RAG（知识库检索）已经能解决大部分贴合问题。
4. **AI 生成的课程资源是"生成合成内容"** → 必须**显式标识（学员端可见）+ 隐式标识（文件元数据含 AIGC）+ 台账留痕（谁用哪个模型哪一版生成、谁审的）**，
   三件缺一即不合规。**未完成登记前，AI 生成的教学内容不得对公网学员上架。**

## 一、选型前置（**硬条件，不满足直接排除**）

| # | 前置条件 | 为什么 |
|---|---|---|
| 1 | 模型本体**必须已在国家网信办完成备案**（在官方公告清单内） | 调用**未备案**模型，登记根本办不下来 |
| 2 | 服务商能提供**企业级 SLA、数据不出境、不用于训练**的书面承诺 | 课程语料是自有资产，不能被拿去训练 |
| 3 | 支持**流式输出（SSE）** | AI 答疑首字延迟直接决定体感（§11.4 已列为上线前必测） |
| 4 | 支持**结构化输出（JSON）** | 自动体检 / 建议判定 / 生成章稿都要机器可解析 |
| 5 | **Embedding 与主模型同栈**（或至少同厂商） | ⚠️ **换 Embedding = 语义空间变了 = 知识库必须全量重建** |
| 6 | 与**内容安全服务同栈**（可双向审核） | 少一个供应商，少一套密钥与合规面 |
| 7 | 接口**OpenAI 兼容**（或网关可适配） | **可替换性**：换模型只改配置，不改业务代码 |

## 三、定案（**主 / 兜底 / Embedding / 审核**）

| 角色 | 定案 | 说明 |
|---|---|---|
| **主模型** | **阿里云百炼 · 通义千问 Qwen 系列** | 日常答疑与生成；按场景选档（简单问答走便宜档，生成章稿走强档） |
| **兜底 / 双活** | **火山引擎 · 豆包 Doubao 系列** | 主模型超时 / 限流 / 故障时自动切换；也用于高峰分流 |
| **第三备选** | 深度求索 DeepSeek | **只做配置备用**，不日常使用（避免三套密钥与三套合规面） |
| **Embedding** | **与主模型同厂商**（百炼） | ⚠️ **换 Embedding 必须重建知识库**（§7.5）；重建耗时**本机未实测**，列为上线前必测 |
| **内容安全** | **云厂商内容安全 + 自建课程词表**（双向：输入 + 输出） | 词表含**试题片段规则**（讨论区防泄题，§9.10.1） |
| **明确不做** | ① **微调**；② **私有化部署**；③ **自研模型**；④ 多模态生成（不生成图 / 视频） | ① 会把"登记"变"备案"（见 §〇-3）；② ②③ 同理且成本与运维翻倍 |

**可替换性是硬要求**（不是美德）：
- AI 网关里用**模型别名**（如 `assistant.fast` / `assistant.strong`）对外，**业务代码只认别名**；
- 换厂商 = **改配置 + 跑一次回归问答集**，**不改业务代码**；
- 上线前要**实测一次主备切换**（记录耗时），与"换 Embedding 重建知识库"一样进 §11.4 未实测清单。

## 四、平台侧备案 / 登记要求

### 4.1 权威依据（现行有效）

| 依据 | 关键内容 |
|---|---|
| 《生成式人工智能服务管理暂行办法》 | 向境内公众提供生成式 AI 服务，需依法开展**安全评估**并按算法推荐管理规定履行**备案**手续 |
| **国家网信办公告（2026 年 7–8 月，2026-09-14 发布）** | **"对于通过 API 接口或其他方式直接调用已备案模型能力的生成式人工智能应用或功能，由地方网信办开展登记"**；2026 年 7–8 月新增 **124 款备案 / 133 款登记**；**截至 2026-08-31，累计 1112 款备案 · 731 款登记** |
| 同一公告（**公示义务**） | **"已上线的生成式人工智能应用或功能，应在显著位置或产品详情页面公示所使用已备案或登记生成式人工智能服务情况，注明模型名称、备案号或上线编号"** |
| 《互联网信息服务算法推荐管理规定》 | 算法备案时限：**提供服务之日起 10 个工作日内**；审查 **30 个工作日**；变更 10 个工作日；终止 20 个工作日注销 |

### 4.2 备案 vs 登记（**我们属于后者**）

| 维度 | **备案** | **登记**（← **本平台**） |
|---|---|---|
| 适用对象 | 自研大模型，或对第三方模型做**预训练 / 优化训练（微调）** | **仅调用第三方 API** 的生成式 AI 应用或功能 |
| 审核层级 | 省级初审 → **国家网信办终审** | **属地（省级）网信办单级** |
| 材料 | 备案表 + 安全评估报告 + 模型服务协议 + 语料标注规则 + 拦截关键词列表 + 评估测试题 | **登记表 + 模型服务协议**（+ 属地要求的补充材料） |
| 周期量级 | **6~8 个月**（含专家评审） | **数周量级**（属地各异，**以属地答复为准**） |

> ⚠️ **一句话记住**：**没有自己造模型、也没有微调 → 只做登记**。
> **一旦微调，就跳到备案那一栏，工期从"数周"变"数月"** —— 这就是 §〇-3 那条决策的全部理由。

### 4.3 本平台必须完成的清单

| # | 事项 | 依据 | 谁办 | 时限 | 状态 |
|---|---|---|---|---|---|
| 1 | **大模型登记**（调用已备案模型） | 网信办公告 | 公司 → **属地网信办** | **上线前** | ⏳ |
| 2 | 算法备案（**若属地认定需要**，例如是否被认定具舆论属性） | 算法推荐管理规定 | 公司（`beian.cac.gov.cn`） | 提供服务起 **10 个工作日**内 | 待属地确认 |
| 3 | **公示**：模型名称 + 备案号 + 上线编号 | 网信办公告 | 技术侧（页脚 + `/about` + 产品详情页） | **上线前** | ⏳ |
| 4 | **生成内容标识**（显式 + 隐式） | 《标识办法》+ 强标 | 技术侧 | 随功能上线 | ⏳ |
| 5 | **教育 App 提供者备案** | 教技厅〔2019〕3号 | 公司 → 属地省教育厅（`app.eduyun.cn`） | 上线前（**若走校园渠道则必需**） | ⏳ |
| 6 | **网络安全等级保护定级备案 + 测评** | 等保条例；**且为第 5 项的前置** | 公司 | 第 5 项之前 | ⏳ |
| 7 | **ICP 备案**（含所用子域） | 工信部 | 公司 | 第 5、6 项之前 | 待确认 |

- **变更义务**：**换底座模型 / 服务场景大规模扩展** → **办理变更**（算法备案口径：变更之日起 10 个工作日内）；
  **服务终止** → 注销（20 个工作日内）。
- **持续义务**：**年度自查** + **运行台账留存** + 接受抽检。台账见 §五。

## 五、AI 生成课程资源的备案与标识要求（**刘老师点名的那一节**）

> **为什么单独一节**：AI **答疑**说错话，影响一个学员；
> AI **生成的教学内容**会**印进课程、进测评范围、影响发证** —— 它是"生成合成内容"里风险最高的一类。

### 5.1 四层要求

| 层 | 要求 | 落点 |
|---|---|---|
| **① 服务层** | 平台**完成大模型登记**；**未登记前，AI 生成的教学内容不得对公网学员上架**（可先邀请制 / 校内试运行） | §4.3 |
| **② 标识层（显式）** | 学员端在生成内容处**显著标注**"**AI 辅助生成，经教师与管理员审核**"；文本需在**起始 / 末尾或适当位置**给提示，**字体清晰可辨，不得刻意缩小或模糊** | §7.16 P-4 · 学习页与讲义头 |
| **③ 标识层（隐式）** | 导出的文件（讲义 / 课件 / 导出包）在**元数据**中写入含 **`AIGC`** 的字段，内容含：生成合成内容属性信息、**服务提供者名称/编码**、**内容编号**、**数字签名或哈希校验值** | `asset` 导出管线 |
| **④ 台账层（举证）** | 每次生成可追：**建议/数据 → 模型（名称 + 版本 + 备案号/登记号）→ 输出 → 人工修改 → 教师一审 → 管理员二审**；**可整体导出备查** | `ai_content_draft` / `ai_content_review` |

- **不得恶意删除、篡改、伪造、隐匿标识**（《标识办法》明文禁止）。
- **生成内容不得包含个人信息**（不得把学员评论里的手机号 / 证件号带进生成稿）；
  语料**仅来自自有课程资产**（已定，§9.8）。

### 5.2 为什么"不做微调"这件事在合规上这么关键

| 方案 | 触发义务 | 周期量级 | 结论 |
|---|---|---|---|
| 调用已备案模型 + **RAG（知识库检索）** | **登记**（属地单级） | 数周 | ✅ **首发采用** |
| 在第三方模型上**微调** | **备案**（省级 + 国家终审，含专家评审） | **6~8 个月** | ❌ 首发不做 |
| **自研 / 私有化模型** | **备案** + 更重的算力与安全责任 | 更长 | ❌ 首发不做 |

> **课程贴合度靠"语料 + 引用 + 双审"解决，不靠微调** ——
> 我们的答案本来就要求**带课程内出处**（§7.5），RAG 天然适配这个口径。

### 5.3 门禁（写成脚本 / 测试）

- [ ] **模型配置必须能追到备案信息**：调用前校验模型在"已备案清单"内，
      并把 `model` / `model_version` / `filing_no` **写进每次调用记录**；不在清单内 → **拒绝调用 + 告警**
- [ ] **合规信息未配置时 AI 不对公网启用**（fail-closed，与"强制密钥缺失则拒绝启动"同一逻辑）
- [ ] **登记号 / 备案号 / 模型名称在页脚与 `/about` 可查**（公示义务，不是可选）
- [ ] **AI 生成资产导出的元数据含 `AIGC` 字段**（有测试）
- [ ] **学员端显式标识存在**（截图留档，纳入上线检查清单）
- [ ] **台账可一键导出**（含双审记录与模型信息），供监管抽查

## 六、教育行业的附加合规（**这一节有个必须拍板的冲突**）

### 6.1 教育 App 备案

- 依据：**《教育移动互联网应用程序备案管理办法》（教技厅〔2019〕3号）**，通过
  **教育部教育移动互联网应用程序备案管理平台**（`app.eduyun.cn`）办理：
  **提供者备案**（住所地 / 注册地**省级教育行政部门**）+ **使用者备案**（学校侧）。
- **提供者备案的前置**：**先完成 ICP 备案 + 网络安全等级保护定级备案**。
- 备案编号需**在教育 App 内公示**。
- **判断**：本产品是"以学生学习为主要应用场景的移动应用"，**属于教育 App 范畴** →
  **只要将来要进校园（学校推荐 / 统一使用），提供者备案就是必需的**。

### 6.2 ⚠️ 必须拍板的冲突：**入校场景与"付费模式"不兼容**

多地教育行政部门对**入校（进校园选用）**的教育 App 有明确红线，原文口径包括：

- **"选用的教育 APP 不得向学生及家长收取任何费用"**（北京市教委细则第二十四条）；
- **"不得借家委会名义组织家长购买"**、**"不得统一组织免费试用等诱导家长和学生购买"**；
- **"不得与学分、成绩和评优评先挂钩"**（北京市教委细则；珠海、沈阳同口径）。

**我们的商业模式核心是"学员付费解锁 + 企业能力认证"** →
**若走"学校统一要求学生使用"这条路，与上述规定直接冲突。**

| 路径 | 可行性 | 说明 |
|---|---|---|
| **A. 面向个人自主购买**（现方案） | ✅ 可行 | 学员自愿购买，不经学校组织、不与学分挂钩 —— **不落入"入校选用"的限制** |
| B. 学校统一要求使用 + 学生付费 | ❌ **不可行** | 直接违反"不得向学生及家长收取任何费用" |
| C. 学校统一使用 + **学校 / 企业付费**（B2B2C） | ✅ 可能可行 | 由学校或企业统一采购，学员免费 —— **需另设合同与发票口径（当前 PRD 无此设计）** |
| D. 企业内训 / 校企合作（企业方付费） | ✅ 可行 | 与"企业认证"定位天然契合 |

> **建议（待拍板）**：**首发走 A（个人自主购买）**，
> **把 C / D 作为第二阶段**（需新增"机构采购 + 学员免单"的权益与开票模型，是一块独立工作量）。
> **明确不做"学校要求学生付费"** —— 那不是运营策略问题，是合规红线。

### 6.3 未成年人

沿用 §9.9：**按仅成人设计**。若将来进校园，**必然涉及未成年人** →
需补**监护人同意**、个人信息处理规则、AI 留存策略，且"青少年模式"类要求另算。**这将是一个独立里程碑**。
